# Модуль Assets — реестр активов

## Назначение

Хосты в STools живут в нескольких модулях порознь: VM знает их по последней
выгрузке MaxPatrol VM, антивирус — по снапшотам Kaspersky Security Center,
AD — по файлу выгрузки домена, и общего ключа между ними нет. Assets сводит
их в один реестр: актив — хост с именем и/или IP, а к нему привязаны
наблюдения источников — последнее, что о хосте сказал каждый из VM, KSC, AD,
DNS и RackTables. Каноническая карточка актива собирается из самого свежего
наблюдения, поэтому видно, какой источник отстал (в DHCP-сетях IP меняется, а
VM и антивирус ещё показывают старый). Сканирования сети в модуле нет.

Обновление через DNS, проход RackTables и синхронизация с модулями — задачи
модуля. Их запускают вручную или по
расписанию: расписания хранит
планировщик платформы (`platform_schedule`), который раз в минуту запускает
просроченные задачи и переживает перезапуск API. Окно расписания (например,
только ночью) задаётся в часовом поясе `STOOLS_TZ` из окружения API, по
умолчанию UTC. Читают реестр все роли;
сети, DNS-серверы, настройки, ручные поля актива и запуск задач — аналитик и
администратор.

## Страницы

**Обзор** (`/assets`) — счётчики со ссылками в список: всего активов, с
любым расхождением, по зонам и источникам, с расхождениями между
источниками, без агента антивируса, неактивные компьютеры AD. Счётчики расхождений не включают решённые людьми
(«Принят риск», «Ложное срабатывание» — настройка подсчётов платформы); их
число — строкой «принято рисков: N, в работе: N» со ссылками в список. Ниже —
последние обновления DNS, время последней синхронизации с модулями и
кнопка «Синхронизировать».

**Активы** (`/assets/list`) — таблица реестра: имя, FQDN, IP, сеть и группа сети,
ОС, источники значками (серый — источник перестал видеть хост или его данные
устарели), когда актив видели в последний раз, число расхождений. Поиск и
фильтры по источнику, коду расхождения, статусу расхождений («мои»,
«просроченные»), расположению (внутренняя / DMZ / внешняя / не задано — по группе сети
актива), группе сети, сети (выбор поиском: адрес, имя, тег, VLAN), тегу, критичности и LAPS. Панель
фильтров свёрнута и раскрывается кнопкой «Фильтры» (выбор запоминается в
браузере); пока она свёрнута, действующие фильтры видны метками под строкой
поиска. Флажки строк отмечают активы для массового изменения критичности,
тегов и статуса расхождения (Shift — диапазон, «отметить все по фильтру» —
не только загруженные строки). Строка открывает карточку: каноническая шапка,
расхождения со статусами, таблица «по источникам» с подсветкой устаревших и
противоречащих значений, ссылки на хост в модулях VM,
антивирус и AD, ручные поля и действия — объединить активы, отвязать
наблюдение, задать сеть (поиском; выбранная сеть видна всегда). В шапке карточки —
сеть (ссылка в её карточку), группа сети и расположение хоста с признаками группы
(«доступна из интернета», «конфиденциальные данные»). Если адрес актива не входит ни в одну
сеть, рядом ссылка «создать сеть» — карточка новой сети с подставленным /24; после
сохранения актив привязывается к ней сам.

**Пользователи** (`/assets/users`) — учётки AD и сеансы KSC, привязанные к
активам-хостам; см. раздел «Пользователи» ниже.

**Группы** (`/assets/groups`) — доменные группы из AD и локальные группы
хостов из MaxPatrol VM; см. раздел «Группы» ниже.

**Сети** (`/assets/networks`) — две вкладки, «Сети» и «Правила групп».

Вкладка «Сети» — список по страницам с общим числом (сетей тысячи) и колонками CIDR, название,
группа, расположение, VLAN, площадка, теги, активов. Поиск: адрес (IP — сети, которые его
содержат, от узкой к широкой), часть CIDR, имя, описание, тег (явный и унаследованный), VLAN.
Фильтры: группа сетей, расположение, источник группы (вручную / по правилу / публичный адрес
RackTables / не назначена), откуда сеть (вручную / RackTables); панель «Фильтры» свёрнута, действующие
фильтры видны метками; выгрузка — по тем же фильтрам. Строка открывает карточку сбоку (`?id=<id>` —
сразу): CIDR, название, описание, группа и почему она такая («вручную», «правило №3: имя начинается
с APP_DMZ_», «публичный адрес (RackTables)»), признаки группы, VLAN, площадка, владелец, теги явные и
унаследованные, откуда сеть (у RackTables — id там и время импорта), число активов (ссылка в
список активов сети), объемлющие и вложенные сети. Аналитик правит в карточке поля и группу —
«по правилам» или вручную (группа, выбранная вручную, главнее правил, пока её не вернут «по
правилам»), удаляет сеть, создаёт новую кнопкой «Добавить сеть». У сети RackTables CIDR, название,
описание, VLAN и теги перезапишет следующий импорт — об этом подпись в форме. Ширина сети не
ограничена: сеть-контейнер (например, 10.0.0.0/8) служит объемлющей, актив привязывается к самой
узкой. Сканирования сетей нет.

Вкладка «Правила групп» — правила отнесения сети к группе: имя начинается с / содержит / подходит
под шаблон со звёздочкой (`*` — любые символы, `?` — один символ; без учёта регистра), есть тег,
сеть внутри CIDR. Проверяются по порядку (стрелки меняют порядок), срабатывает первое включённое
подошедшее; публичная сеть RackTables без
подошедшего правила — в External. Перед сохранением «Проверить» показывает, сколько сетей
подпадёт (с учётом правил выше, без сетей с ручной группой) и первые 20 с их нынешней группой.
Любая правка правил сразу пересчитывает группы; «Применить правила» — пересчитать вручную.

**Задачи** (`/assets/jobs`) — фоновые задачи модуля (обновление DNS, проход
RackTables, синхронизация с модулями): идущие сверху, с прогрессом и ошибками;
аналитик может снять идущую задачу.

**Настройки → Assets** (`/settings/assets`) — DNS-серверы (прямые запросы к
серверу или чтение зон AD через подключение модуля AD) с расписанием и
запуском, пороги устаревания и неактивности, синхронизация с модулями VM,
антивирус и AD с временем последнего обновления по источникам и
расписанием, группы сетей с признаками (расположение, доступ из интернета, конфиденциальные
данные; в расчёт рисков VM не идут).

Хост антивируса (карточка хоста KSC) и хост VM (карточка уязвимости и
фильтр по хосту) показывают ссылку «в Assets», если хост сопоставлен с
активом: она открывает список с карточкой этого актива. Контракт API —
`docs/assets/api.md`.

## Как пользоваться

1. **Описать сети** (`/assets/networks`) вручную или проходом RackTables и
   завести правила групп (вкладка «Правила групп»). Без сетей реестр работает, но у
   активов будет код «сеть не описана», а фильтры по группе и расположению пусты.
2. **Синхронизация** с модулями VM, антивирус и AD. После импорта в любом из
   них она запускается сама (настройка «синхронизировать сразу после
   импорта»); вручную — кнопкой на обзоре или «Обновить сейчас» в настройках;
   по расписанию — в тех же настройках. Если в этот момент записываются
   результаты DNS или RackTables, синхронизация дожидается их, а не пропускается.
   Появляются активы и расхождения между источниками.
3. **DNS** (`/settings/assets`): сервер для прямых и обратных запросов или
   чтение зон AD через подключение модуля AD. Обновление даёт актуальные
   адреса (старые в VM и антивирусе подсвечиваются как устаревшие) и имена
   хостам, известным только по адресу. Темп сервера считает запросы: на имя — A и
   AAAA (два), на адрес — PTR (один); задача пишет оценку «~N запросов при
   R/с ≈ T мин» (без учёта таймаутов).

Пороги «устаревания» и «неактивности AD» задаются в настройках и меняют
расхождения сразу — они считаются при чтении.

## Пользователи

Пользователь — отдельный вид актива: учётка из выгрузки AD (включена или
отключена, группы, привилегированность) и сеансы и владение устройствами из
снапшота антивируса (сборщик KSC 1.4 и новее), привязанные к активам-хостам.
Данные — из последней синхронизации с модулями, ни AD, ни KSC при просмотре
не спрашиваются. Одна учётка из AD и KSC склеивается по SID, без SID — по
домену и имени; локальная учётка хоста — отдельный пользователь на каждом
хосте; группы с сеансом и служебные учётки KSC пользователями не считаются.

**Список** (`/assets/users`) — учётка, имя, UPN, домен, локальная ли,
состояние в AD (включена, отключена, неизвестно — AD учётку не видел),
привилегированная ли, источники значками, на скольких хостах учётка в системе
на момент сбора и со скольких хостов вообще связана, когда видели, число
расхождений; те же колонки у выгрузки CSV/XLSX. Поиск по учётке, имени, UPN и
SID; фильтры по расхождениям, источнику, состоянию в AD, сеансу (в системе на
момент сбора, заходил раньше, сеансов нет), привилегированности и локальности.
Панель фильтров свёрнута, как у активов; действующие фильтры видны метками.

**Карточка пользователя** — кто по AD (состояние, привилегированность,
локальная ли, SID), расхождения, устройства со ссылками на карточки активов
и отметкой «в системе на момент сбора», «заходил раньше» или «владелец»,
группы AD — прямые (с основной) и через вложенные группы отдельно, флаги из
выгрузки (пароль не истекает, последний вход, adminCount), заметка и теги
(аналитик и администратор). Если список участников какой-то группы домена мог
быть обрезан (ровно 1500 или 5000 участников), карточка показывает оговорку.
Приглушены связи, которые пропали, и устаревшие — на хосте, где пользователи
больше не собираются, связь старше порога устаревания: она показывается, но
в расхождениях не участвует.

**В карточке актива** — блок «Пользователи»: в системе на момент сбора,
заходили раньше, владелец по KSC, пропавшие — приглушённо; ссылки ведут в
карточку пользователя, «все пользователи хоста» — в список с фильтром по
хосту. «Пользователи не собраны» — по хосту нет снапшота антивируса со
сбором пользователей (старый сборщик, нет агента, запрос по хосту отказал);
это не «пользователей нет», и такие связи не помечаются пропавшими. Там же —
группы с сеансом (их отдаёт KSC, пользователями они не считаются) и пометка,
если владелец задан в KSC, но среди пользователей хоста его нет.

**Расхождения пользователей** считаются при чтении и пока без статусов
платформы: сеанс учётки, отключённой в AD; учётки с сеансами нет в AD (только
для доменов, чья выгрузка прочитана; локальные не судятся); привилегированная
учётка с сеансом на рабочей станции (ОС Windows или macOS без «server»);
владелец устройства по KSC без сеанса на нём (хост без сбора пользователей не
судится). Условия и тексты — `docs/assets/api.md`, раздел «Пользователи».

## Группы

Группа — отдельный вид актива: доменная из выгрузки AD и локальная группа
хоста из MaxPatrol VM (Windows — с SID, Linux — с описанием «GID n»).
Доменная группа, которую VM видит участником локальных групп, а в выгрузках
AD её нет, помечается «нет в AD». Данные — из последней синхронизации, ни AD,
ни VM при просмотре не спрашиваются.

**Список** (`/assets/groups`) — имя, домен или компьютер (у локальной — имя
хоста ссылкой на карточку актива), вид (локальная, доменная), число прямых
участников, источники, SID, описание; те же колонки у выгрузки CSV/XLSX.
Поиск по имени и SID; фильтры по виду, источнику, наличию участников и
состоянию (без выбора — только живые группы, пропавшие — выбором). Панель
фильтров свёрнута, как у активов; действующие фильтры видны метками.

**Карточка группы** — шапка (имя, домен или хост, вид, SID, описание,
источники, когда видна впервые и последний раз, дата пропажи; у локальной —
«снимок VM от …»: последний снимок групп VM, где её семейство ОС получено
полностью) и блоки:
- «Состав» — прямые участники: пользователи (ссылкой в карточку
  пользователя), группы (в карточку группы), компьютеры (в карточку хоста),
  встроенные субъекты с пояснением («все прошедшие проверку пользователи и
  компьютеры»), неизвестные; «основная группа» — участник через основную
  группу учётки. Больше 1000 участников — «показаны 1000 из N». У локальной
  группы Linux основная группа пользователя (по GID учётки) в составе не
  видна — карточка это оговаривает.
- «Полный состав» — по кнопке: пользователи и компьютеры через все
  вложенные группы, у каждого «через …» (кратчайшая цепочка) и «путей N»,
  постранично («показать ещё»); сверху встроенные субъекты с пояснением,
  внизу тупики — неизвестный участник, группа без записи, «нет в AD»,
  пустая. Циклы и ромбы вложенности не мешают: каждая группа раскрывается
  один раз.
- «Куда входит» — доменные группы (прямо и через вложенность) и локальные
  группы на хостах, где группа состоит сама или через доменную группу.
- «Права» — двумя отдельными подписанными списками, не смешиваясь:
  «По факту (VM)» — локальные группы хостов по данным VM, сводом
  («Administrators на 1 200 хостах · через Helpdesk», первые хосты ссылками
  и «и ещё N»); «По политике (GPO)» — записи Restricted Groups и GPP:
  локальная группа, имя GPO, способ и действие, хосты, пометка «фильтр
  безопасности» (список хостов может быть шире действующего). Оговорки
  разбора GPO (ссылки GPO неизвестны, файлы не прочитаны) — под списком
  политики как есть. У локальной группы «по факту» — её состав в блоке
  «Состав» на её хосте, «по политике» — записи GPO, которые назначают
  участников этой группе на этом хосте.

Пропавшие локальные группы определяются по семейству ОС (Windows, Linux)
отдельно и только по полному снимку семейства: если запрос семейства не
прошёл, выгрузка оказалась не того формата (пустая, HTML, без нужных
столбцов) или пустой при непустом прежнем снимке, остаётся прежний снимок; с
лимитом подключения снимок неполный — группы пишутся, но пропавшими по нему
не считаются.

**В карточке пользователя** имя группы AD — ссылка в карточку группы; группа
без записи в разделе (например, встроенная чужого домена) — текстом. **В
карточке актива** — ссылка «локальные группы хоста»: список с фильтром по
хосту. Контракт — `docs/assets/api.md`, раздел «Группы».

## Статусы расхождений

Расхождение — находка с общими статусами платформы
([docs/platform/findings.md](../platform/findings.md)): «Новая», «В работе»,
«Принят риск», «Ложное срабатывание», «Исправлено»; «Устранена» и
«Переоткрыта» ставит система. Ключ — актив и код расхождения (у
расхождений полей ещё источник и поле): смена значения или даты в тексте
расхождения — та же находка.

**Принять риск** (например, хост без агента антивируса на изолированном
стенде): в карточке актива щёлкнуть строку расхождения — раскроется «Работа
с находкой»; выбрать «Принят риск», написать обоснование, при необходимости
срок («риск принят до»), «Сохранить». Многим активам сразу — отметить их в
списке и в полосе массовых действий выбрать «Расхождение: <код> → Принят
риск» с обоснованием. Расхождение с таким статусом уходит из счётчиков
списка и обзора, но остаётся в карточке приглушённым, со статусом; найти
такие — фильтр «Статус расхождений» в списке.

Статусы сверяются с расхождениями в конце синхронизации, прохода RackTables и
обновления DNS и после ручных правок реестра (объединение, отвязка,
закрепление поля, смена сети актива): пропавшее расхождение в работе
становится «Устранена», вернувшееся — «Переоткрыта»; принятый риск
исчезновением не трогается.

**Объединение активов**: решения по расхождениям поглощённого актива
переходят к оставшемуся (событие истории «решение перенесено»); если у
оставшегося уже есть решение по тому же расхождению, оно остаётся, а
прежнее — при поглощённом активе и закрывается сверкой. При отвязке
наблюдения решения не переносятся.

## Расписания

Окна расписаний задаются в поясе `STOOLS_TZ` из окружения API (по
умолчанию `UTC`; для Москвы — `STOOLS_TZ=Europe/Moscow` в `ops/.env`);
в базе время хранится в UTC.

**Кластеры Windows.** Наблюдение AD несёт признак `cluster` (учётка кластера), `role`
(роль кластера) или `node` (узел) по SPN компьютера — его находит проверка `Clusters`
модуля AD. Учётка кластера и роль — виртуальные имена, не хосты: у них не бывает
расхождений «нет агента антивируса» и «неактивный компьютер AD».

**LAPS.** Наблюдение AD несёт признак `laps`: у компьютера есть срок пароля LAPS (`lapsExpiry`
старого LAPS или `lapsNewExpiry` Windows LAPS) — пароль локального администратора им управляется.
В списке активов фильтр «LAPS: есть / нет» (параметр `laps=yes|no`) считает только активы с
живым наблюдением AD; наблюдения, записанные до появления признака, получают его при следующей
синхронизации.

**RackTables** (настройки → RackTables). Проход по JSON API заказчика (`json_api.php`, HTTP
Basic, учётка AD): все сети `listCells(ipv4net)` создаются в Assets с названием, VLAN,
комментарием и тегами (пометка «RackTables» в списке сетей; повторный проход обновляет эти поля,
зону и площадку не трогает; сеть, описанная вручную с тем же CIDR, остаётся вашей; сеть IPv4
шире /16 заводится как объемлющая, но адреса по ней не запрашиваются). Запросы идут строго по
одному с заданным темпом (по умолчанию 10/с). По каждой сети читаются адреса `getIPAddressList`: адрес с
именем становится наблюдением источника RT (имя, IP, комментарий, сеть и VLAN) и сопоставляется
с активами по имени и IP; адрес только с IP не переносится. Пропавший из RackTables адрес
получает `gone_at`. Группу сети назначают правила групп; публичная сеть без подошедшего правила
попадает в группу **External** (если она есть в справочнике); публичный и частный адрес одного хоста — NAT, а не расхождение: «устарели»
и «расходятся» по IP считаются только между адресами одной области. Источник RT — самый младший по приоритету и не считается доказательством
живого хоста: «нет агента антивируса» он не даёт. Объекты RackTables не переносятся: API не отдаёт их привязки к адресам.
