# Модуль Assets — реестр активов

## Назначение

Хосты в STools живут в нескольких модулях порознь: VM знает их по последней
выгрузке MaxPatrol VM, антивирус — по снапшотам Kaspersky Security Center,
AD — по файлу выгрузки домена, и общего ключа между ними нет. Assets сводит
их в один реестр: актив — хост с именем и/или IP, а к нему привязаны
наблюдения источников — последнее, что о хосте сказал каждый из VM, KSC, AD,
сканера сети и DNS. Каноническая карточка актива собирается из самого свежего
наблюдения, поэтому видно, какой источник отстал (в DHCP-сетях IP меняется, а
VM и антивирус ещё показывают старый) и какие хосты в сети вообще никто не
описал.

Сканер сети (ICMP и TCP из контейнера API), обновление через DNS и
синхронизация с модулями — задачи модуля. Их запускают вручную или по
расписанию: расписания хранит
планировщик платформы (`platform_schedule`), который раз в минуту запускает
просроченные задачи и переживает перезапуск API. Окно расписания (например,
только ночью) задаётся в часовом поясе `STOOLS_TZ` из окружения API, по
умолчанию UTC. Читают реестр все роли;
сети, DNS-серверы, настройки, ручные поля актива и запуск задач — аналитик и
администратор.

## Страницы

**Обзор** (`/assets`) — счётчики со ссылками в список: всего активов, с
любым расхождением, по зонам и источникам, хосты, которые видит только
сканер, не отвечающие по известному адресу, с расхождениями между
источниками, без агента антивируса,
неактивные компьютеры AD. Счётчики расхождений не включают решённые людьми
(«Принят риск», «Ложное срабатывание» — настройка подсчётов платформы); их
число — строкой «принято рисков: N, в работе: N» со ссылками в список. Ниже —
последние сканы и обновления DNS, время последней синхронизации с модулями и
кнопка «Синхронизировать».

**Активы** (`/assets/list`) — таблица реестра: имя, FQDN, IP, сеть и зона,
ОС, источники значками (серый — источник перестал видеть хост или его данные
устарели), когда актив видели в последний раз, число расхождений. Поиск и
фильтры по источнику, коду расхождения, статусу расхождений («мои»,
«просроченные»), сети, зоне, открытому порту, тегу и критичности. Панель
фильтров свёрнута и раскрывается кнопкой «Фильтры» (выбор запоминается в
браузере); пока она свёрнута, действующие фильтры видны метками под строкой
поиска. Флажки строк отмечают активы для массового изменения критичности,
тегов и статуса расхождения (Shift — диапазон, «отметить все по фильтру» —
не только загруженные строки). Строка открывает карточку: каноническая шапка,
расхождения со статусами, таблица «по источникам» с подсветкой устаревших и
противоречащих значений, данные сканера, ссылки на хост в модулях VM,
антивирус и AD, ручные поля и действия — объединить активы, отвязать
наблюдение, задать сеть. Если адрес актива не входит ни в одну сеть, рядом
ссылка «создать сеть» — форма новой сети с подставленным /24; после
сохранения актив привязывается к ней сам.

**Сети** (`/assets/networks`) — сети с описанием, зоной из справочника,
площадкой, владельцем и VLAN; по каждой — число активов, живых при последнем
скане и найденных только сканером, сколько займёт скан, если никто не
ответит, и отметка «только порты», если последний скан шёл без ICMP. В форме
сети — настройки сканирования (порты, исключения, параллельность, таймауты,
темп) с оценкой длительности и расписание; скан можно запустить сразу.

**Задачи** (`/assets/jobs`) — фоновые задачи модуля (скан сети, обновление
DNS, синхронизация с модулями): идущие сверху, с прогрессом и ошибками;
аналитик может снять идущую задачу.

**Настройки и данные** (`/assets/settings`) — DNS-серверы (прямые запросы к
серверу или чтение зон AD через подключение модуля AD) с расписанием и
запуском, пороги устаревания и неактивности, синхронизация с модулями VM,
антивирус и AD с временем последнего обновления по источникам и
расписанием, справочник зон.

Хост антивируса (карточка хоста KSC) и хост VM (карточка уязвимости и
фильтр по хосту) показывают ссылку «в Assets», если хост сопоставлен с
активом: она открывает список с карточкой этого актива. Контракт API —
`docs/assets/api.md`.

## Как пользоваться

1. **Описать сети** (`/assets/networks`): CIDR, название, зона, площадка,
   владелец. Без сетей реестр работает, но у активов будет код «сеть не
   описана», а фильтр по зоне пуст. Сканирование в форме сети по умолчанию
   выключено.
2. **Синхронизация** с модулями VM, антивирус и AD. После импорта в любом из
   них она запускается сама (настройка «синхронизировать сразу после
   импорта»); вручную — кнопкой на обзоре или «Обновить сейчас» в настройках;
   по расписанию — в тех же настройках. Если в этот момент записываются
   результаты скана или DNS, синхронизация дожидается их, а не пропускается.
   Появляются активы и расхождения между источниками.
3. **Скан** описанной сети: включить сканирование в форме сети, запустить
   «сканировать сейчас», посмотреть задачу и результат — новые хосты
   («только сканер») и известные, которые не отвечают. Затем — расписание
   с окном (например, ночью).
4. **DNS** (`/assets/settings`): сервер для прямых и обратных запросов или
   чтение зон AD через подключение модуля AD. Обновление даёт актуальные
   адреса (старые в VM и антивирусе подсвечиваются как устаревшие) и имена
   хостам, найденным сканером. Темп сервера считает запросы: на имя — A и
   AAAA (два), на адрес — PTR (один); задача пишет оценку «~N запросов при
   R/с ≈ T мин» (без учёта таймаутов).

Пороги «устаревания» и «неактивности AD» задаются в настройках и меняют
расхождения сразу — они считаются при чтении.

## Статусы расхождений

Расхождение — находка с общими статусами платформы
([docs/platform/findings.md](../platform/findings.md)): «Новая», «В работе»,
«Принят риск», «Ложное срабатывание», «Исправлено»; «Устранена» и
«Переоткрыта» ставит система. Ключ — актив и код расхождения (у
расхождений полей ещё источник и поле): смена значения или даты в тексте
расхождения — та же находка.

**Принять риск** (например, хост без агента антивируса на изолированном
стенде): в карточке актива щёлкнуть строку расхождения — раскроется «Работа
с находкой»; выбрать «Принят риск», написать обоснование, при необходимости
срок («риск принят до»), «Сохранить». Многим активам сразу — отметить их в
списке и в полосе массовых действий выбрать «Расхождение: <код> → Принят
риск» с обоснованием. Расхождение с таким статусом уходит из счётчиков
списка и обзора, но остаётся в карточке приглушённым, со статусом; найти
такие — фильтр «Статус расхождений» в списке.

Статусы сверяются с расхождениями в конце синхронизации, скана и
обновления DNS и после ручных правок реестра (объединение, отвязка,
закрепление поля, смена сети актива): пропавшее расхождение в работе
становится «Устранена», вернувшееся — «Переоткрыта»; принятый риск
исчезновением не трогается.

**Объединение активов**: решения по расхождениям поглощённого актива
переходят к оставшемуся (событие истории «решение перенесено»); если у
оставшегося уже есть решение по тому же расхождению, оно остаётся, а
прежнее — при поглощённом активе и закрывается сверкой. При отвязке
наблюдения решения не переносятся.

## Первый скан на сервере

Сканер шлёт пакеты в рабочую сеть, поэтому включение идёт лестницей, по
слову владельца на каждую ступень:

1. Одна маленькая сеть (например, /28 или /27 своего сегмента), запуск
   вручную, просмотр задачи и найденного.
2. Только после этого — расписание для этой сети, затем остальные сети.

Скан — ICMP echo, TCP-рукопожатие по портам из настроек сети (соединение
закрывается сразу, данные не отправляются) и PTR; темп ограничен
`rate_per_s`, параллельность — `concurrency`. Сети шире /16 не принимаются.

ICMP из контейнера API работает без root через непривилегированный сокет:
compose задаёт контейнеру `sysctls: net.ipv4.ping_group_range: "0
2147483647"` (dev и prod). Если среда этот sysctl запрещает, сканер
работает в режиме «только порты» — отметка в задаче и `icmp: false` в
ответе запуска; хосты без открытых портов из списка тогда не видны.

Окна расписаний задаются в поясе `STOOLS_TZ` из окружения API (по
умолчанию `UTC`; для Москвы — `STOOLS_TZ=Europe/Moscow` в `ops/.env`);
в базе время хранится в UTC.
