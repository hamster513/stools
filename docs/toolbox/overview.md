# Модуль ToolBox — очистка файлов

## Назначение

Выгрузки, логи и конфиги уходят наружу — вендору, в поддержку, в LLM. Очистка
заменяет в них адреса IPv4/IPv6 и MAC, имена хостов и доменов, учётные записи,
SID, секреты и слова из списка на устойчивые псевдонимы: одно настоящее
значение — один псевдоним во всех файлах и заданиях. По очищенному файлу
по-прежнему можно работать, а ответ — перевести обратно.

## Ход работы

1. **Вход** — файл (текст, json, csv, xml, conf, ini, yaml, log, zip и gz
   с ними, вложенные zip) или вставленный текст. Галочка «учётные записи из
   AD» добавляет в словарь `sAMAccountName` пользователей последнего снапшота
   каждого домена.
2. **Скан** — словари собираются из базы: домены и хосты из AD, Активов и KSC
   (последний снапшот каждого сервера), сети Активов (каждая сеть целиком
   сдвигается по ключу внутри своей частной зоны) и подсети и слова из
   настроек. Находка — уникальное значение: категория, предлагаемый
   псевдоним, число вхождений, до трёх контекстов, первый файл. Без галочки по
   умолчанию — найденное только авто-поиском и адреса, похожие на номер версии.
3. **Предпросмотр** — галочки, правка псевдонимов (не занятых другим значением
   и не содержащих настоящих значений), добавление слов.
4. **Применение** — замена включённых находок, новые псевдонимы — в таблицу
   соответствий той же транзакцией, затем самопроверка: результат сканируется
   заново. Если в нём осталось хоть одно включённое значение — задание
   `failed`, файлы результата удаляются, таблица не меняется.
5. **Результат** — файл того же типа, `report.txt` (по категориям: значений и
   вхождений, без настоящих значений), `mapping.csv` (`kind,real,alias` этого
   задания, без секретов).
6. **Срок жизни** — каталог задания (`data/toolbox/<id>/`) удаляется через
   `retention_days` (по умолчанию 7) после завершения — расписание платформы
   `toolbox/cleanup` раз в сутки — или кнопкой «удалить файлы». Строка задания
   остаётся.
7. **Обратный перевод** — текст до 1 МБ: псевдонимы → настоящие значения по
   всей таблице. Секреты не переводятся: их метка `<secret-…>` в таблицу не
   пишется.

## Роли

| Действие | Аудитор | Аналитик | Администратор |
|---|---|---|---|
| Список заданий, статусы, находки без контекстов | да | да | да |
| Создание, предпросмотр с контекстами, применение, скачивание, удаление файлов | — | да | да |
| Обратный перевод, таблица соответствий и её выгрузка | — | да | да |
| «Забыть» запись таблицы, настройки | — | — | да |

Журнал действий получает создание, правку находок, применение, скачивание,
удаление файлов, «забыть» и изменение настроек — с номерами и счётчиками, без
настоящих значений.

## Резервная копия

`toolbox_alias` (таблица соответствий) и `toolbox_settings` (ключ HMAC
установки, слова, подсети) обязаны попадать в резервную копию базы: без них
старые очищенные файлы обратно не перевести, а новые задания выдадут тем же
значениям другие псевдонимы. Ключ HMAC генерируется сервером при первом
обращении и наружу не отдаётся.

## Лимиты

- файл — до 200 МБ, распакованное содержимое — до 512 МБ;
- вставленный текст и текст обратного перевода — до 1 МБ;
- «забытый» псевдоним может достаться другому значению: старые файлы с ним
  после этого переведутся иначе.

## Что не покрыто

Офисные форматы (docx, xlsx, pdf), изображения и двоичные файлы — пропускаются
(кроме двоичных адресов `octets` выгрузки KSC); архив только из двоичных файлов
и двоичный файл — задание с ошибкой «в файле нет текста». Не ищутся телефоны,
паспорта и прочие персональные данные вне учёток и слов из списка; путь внутри
URL не меняется.
