# Сборщик выгрузки Kaspersky Security Center

Скрипт `STools-KSC-Collector.ps1` скачивается в интерфейсе: Антивирус →
Настройки и данные → «Скачать». Он не анализирует и не меняет ничего на
сервере KSC: вызывает методы Open API (порт 13299) и пишет один файл
формата `stools-ksc/1` (JSON, gzip) — ответы сервера складываются как есть.

## Требования

- Windows с PowerShell 5.1 или новее, либо любая ОС с PowerShell 7 — скрипт
  ходит к KSC по HTTPS, модуль ActiveDirectory не нужен.
- Сетевой доступ к серверу KSC на порт Open API (по умолчанию 13299).
- Учётная запись KSC с правом чтения (внутренняя или доменная).
- Скрипт хранится в UTF-8 с BOM: без него Windows PowerShell 5.1 читает файл
  в ANSI и ломает кириллицу в строках. При правке сохраняйте BOM (тест
  `test_collector_script_has_utf8_bom`).

## Запуск

```powershell
.\STools-KSC-Collector.ps1 -Server ksc01.corp.local -User audit -Internal
.\STools-KSC-Collector.ps1 -Server 10.0.0.5 -User audit -Domain CORP -SkipTlsCheck -OutputPath C:\Temp\ksc.json.gz
.\STools-KSC-Collector.ps1 -Server ksc01.corp.local -User audit -Internal -SkipProducts   # без продуктов и компонентов (быстрее)
```

Пароль запрашивается интерактивно (`Read-Host -AsSecureString`), если не
передан параметром `-Password`. Для самоподписанного сертификата сервера
добавьте `-SkipTlsCheck`: проверка отключается только для адреса KSC
(`-Server`). В Windows PowerShell 5.1 это обработчик на весь процесс — он
пропускает без проверки только этот адрес, остальные проверяет как обычно,
и по окончании скрипта (в том числе с ошибкой) прежний обработчик
возвращается на место.

Результат — `ksc-<сервер>-<дата>.json.gz` в текущем каталоге; в имени
сервера всё, кроме латиницы, цифр, точки, дефиса и подчёркивания,
заменяется на `_` (имя приходит из ответа KSC). Файл содержит
инвентарь устройств (имена, IP-адреса, версии продуктов и агента) —
обращайтесь с ним как с чувствительными данными.

## Что собирается

Кроме групп, хостов, продуктов, политик, задач и лицензий скрипт (и
онлайн-режим STools) читает: держателей административных ролей и внутренние
учётные записи KSC (только отображаемое имя, логин, UPN и признаки
внутренней/встроенной учётки — почта, телефоны и весь каталог AD не
запрашиваются), состояние обязательной двухэтапной проверки, сертификат
сервера, подчинённые серверы иерархии и точки распространения обновлений. У
хостов дополнительно собираются сборка ОС, архитектура процессора, тип
виртуализации и признак ожидающей перезагрузки с причиной и временем запроса.

Каждая из этих секций читается отдельно: если у учётной записи нет прав на
метод (например, аудитору недоступны учётки или 2FA), секция остаётся
пустой, а сбор остальных данных продолжается — причина попадает в
предупреждения (`Write-Warning` в консоли и `server.warnings` в файле).

Дополнительно (необязательная секция `policy_contents`, можно выключить
`-SkipPolicyContents` / `skip_policy_contents`) — содержимое активных политик
продуктов защиты: все секции настроек каждой политики со сведениями о замках
(`KLPRSS_Mnd`, наследованный замок из `KLPRSS_ValLck*`). Секреты: секция
или ключ на любой глубине её параметров с признаком в имени (`PASSWORD`,
`PASSWD`, `PWD`, `SECRET`, `CRYPTED`, `TOKEN`, `CREDENTIAL`, `PRIVATE`,
`PASSPHRASE`, `APIKEY`, `API_KEY`, `AUTH`, `PIN`, `KEY` — подстрокой, без
учёта регистра) переводит всё, что под ним, в режим скрытия: каждая строка
заменяется на `"<скрыто>"`, ключи остаются. Двоичные значения скрываются
всегда, под любым ключом. Тем же правилом скрываются параметры задач
(`TASK_ADDITIONAL_PARAMS`, `TASK_INFO_PARAMS`), и STools повторяет скрытие
при разборе загруженного файла — файл старого сборщика или поправленный
руками секретов не покажет. Так скрываются и пароль в контейнере
настройки (`AdminPassword → KLPRSS_Val`), и секрет в обёртке `params`, и
вложенный хеш (`PasswordProtection → KLPRSS_Val → PasswordHash`), и всё
содержимое секции вроде `KLPRSS_Passwords`. Булевы и числа не скрываются:
замкнутая настройка «защита паролем включена» остаётся видна со значением
и замком (строки источника замка под признаком при этом скрыты). Чего
правило не делает: строки под ключами без признака (и без признака выше
по пути) не проверяются — секрет строкой под нейтральным именем сохранится
как есть. Секция хранится как пришла от KSC (те же обёртки типов, что и в
остальных секциях файла): обёртки проходятся насквозь и остаются, списки —
поэлементно, список из одного элемента и пустой список остаются списками,
глубина вложенности не обрезается (`ConvertTo-Json -Depth 100`).
Политика в своей ошибке не мешает остальным: не открылась — её нет в секции
и есть предупреждение; не прочиталась одна секция — она попадает в `errors`
этой политики, остальные секции на месте. Не больше 200 политик и не больше
2 МБ на секцию (компактный JSON): политика за лимитом записывается без
секций с `errors: ["лимит политик"]` и одним предупреждением, секция за
лимитом — строкой в `errors`.

## Файл настроек и второй фактор

Чтобы не набирать параметры каждый раз, их можно записать в файл:

```powershell
.\STools-KSC-Collector.ps1 -InitConfig .\ksc-config.json   # создаёт шаблон
.\STools-KSC-Collector.ps1 -ConfigPath .\ksc-config.json   # сбор по файлу
```

Поля шаблона: `server`, `port`, `user`, `password`, `internal` (внутренняя
учётная запись KSC), `domain`, `totp_secret`, `skip_tls_check`,
`skip_products`, `skip_policy_contents`, `page_size`, `output_path`,
`delete_after_run`. Параметр
командной строки главнее значения из файла. Пустой `password` — пароль будет
запрошен.

Если на сервере включена двухэтапная проверка, KSC на пароль отвечает отказом
с требованием кода. Скрипт сам повторяет вход с кодом TOTP: считает его из
`totp_secret` (секрет в base32, который KSC показывает при подключении
приложения-аутентификатора) либо, если секрета нет, спрашивает шесть цифр из
приложения. Пароль и секрет можно передать и переменными окружения
`STOOLS_KSC_PASSWORD` и `STOOLS_KSC_TOTP_SECRET`; в командной строке они не
передаются.

Файл настроек содержит пароль и секрет второго фактора. `-InitConfig` сразу
закрывает к нему доступ всем, кроме текущей учётной записи (Windows:
`icacls /inheritance:r /grant:r <вы>:(R,W)`, иначе `chmod 600`). После
успешного сбора файл удаляется, если задан `-DeleteConfigAfterRun` или
`delete_after_run: true`; при ошибке сбора он остаётся. Иначе удалите его
сами. В выгрузку ни пароль, ни секрет не попадают.

## Что дальше

Загрузите файл в STools: Антивирус → Настройки и данные → «Загрузить
выгрузку». Появится снапшот сервера; повторные загрузки сравниваются с
предыдущей по времени сбора.

Онлайн-режим (сбор из STools по Open API) даёт ту же выгрузку — проверки в
обоих режимах одни и те же.
