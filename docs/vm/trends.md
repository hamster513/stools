# Трендовые уязвимости

STools получает сообщения от отдельного `stools-threat-collector`. Соединение всегда начинает STools: HTTPS к заданному адресу/порту, напрямую или через настроенный HTTP/HTTPS CONNECT proxy. Сборщик не подключается к STools, не получает инвентарь, находки или результаты сопоставления. Threat Hunting и его расписание не меняются.

## Развёртывание сборщика

`ops/docker-compose.collector.yml` запускается отдельно от основного стека. Постоянный том `collector-data` содержит SQLite WAL, позиции источников, историю версий и (при настройке) Telegram-сессию. Внешний порт задаёт `COLLECTOR_PORT` (по умолчанию 8443); для публикации на 443 задайте `COLLECTOR_PORT=443` и нужный `COLLECTOR_BIND`. Внутри контейнера HTTPS на 8443. Сборщик работает от UID 10001.

1. В каталоге вне git подготовьте `server.crt` и `server.key` для DNS-имени сборщика; ключ доступен только владельцу и UID контейнера. Укажите `COLLECTOR_CERT_DIR`.
2. `docker compose -f ops/docker-compose.collector.yml up -d --build`.
3. Создайте токен командой `docker compose -f ops/docker-compose.collector.yml exec threat-collector stools-threat-collector token --name stools --admin --output /data/stools.token`. Файл создаётся с режимом 600; хранится только хеш токена. Передайте значение через защищённый канал администратору STools. Команда не печатает секрет. Без `--admin` токен имеет только `data:read`; с `--admin` также `sources:write`.
4. «Настройки → VM → Трендовые уязвимости»: HTTPS URL, токен и при необходимости PEM корпоративного CA. Для прокси включите переключатель, задайте схему, адрес, порт, пользователя/пароль и CA HTTPS-прокси. Сохраните и проверьте подключение.
5. Источники из подготовленного каталога изначально выключены. Включите нужные и запустите сбор. В «Настройки → Расписание» включите `Получение трендов`; рекомендуемый интервал — час. Каждый источник имеет собственный интервал (по умолчанию 60 минут).

При ошибке прокси прямого обхода нет. Системные переменные HTTP_PROXY не подменяют настройки клиента STools. Сертификаты проверяются, TLS verification не отключается. При смене URL требуется повторный ввод токена; при смене адреса прокси — повторный ввод его пароля. API настроек возвращает только признаки наличия секретов.

Исходящий прокси самого сборщика задаётся `COLLECTOR_HTTP_PROXY`, CA — `COLLECTOR_CA_FILE` (PEM должен быть смонтирован). Это отдельное соединение, не настройки прокси STools. HTTP-загрузчик ограничивает размер/время (5 MiB для лент/страниц, 32 MiB для месячного CVRF MSRC), запрещает частные и служебные адреса, закрепляет проверенный IP и проверяет редиректы. RSS-сводка сохраняется, даже если полная статья недоступна; неизвестная HTML-разметка отмечается ошибкой.

### Telegram

Используется пользовательская сессия Telethon, только публичные каналы. Владелец самостоятельно получает API ID/API hash и авторизует аккаунт. Секреты размещаются в файлах вне git (600), монтируются в контейнер, пути задаются `COLLECTOR_TELEGRAM_API_ID_FILE` и `COLLECTOR_TELEGRAM_API_HASH_FILE`. Запуск авторизации: `docker compose -f ops/docker-compose.collector.yml exec threat-collector stools-threat-collector telegram-login`. Код входа и 2FA вводятся владельцем в терминале. Сессия хранится в постоянном томе, её резервная копия является секретом. Автоматическая передача сообщений Telegram модели запрещена в конфигурации и коде фонового анализа. Ручной перевод и объяснение публичной публикации доступны по кнопке отдельной задачей ИИ. FloodWait откладывает повтор, позиция не сдвигается при ошибке; новые сообщения догоняются по ID, последние семь дней перечитываются для правок/удалений. Первый сбор ограничен 30 днями.

## Аналитика

«VM → Тренды»: по умолчанию «Обсуждаемые CVE» за последние семь дней. Здесь видны CVE/GHSA с датированными публикациями, даже если оснований для тренда ещё недостаточно. «Трендовые CVE» требует независимых материалов или подтверждённой эксплуатации; «Найдено у нас» дополнительно проверяет локальные находки. «Ранние сигналы / На проверку» содержит ещё не квалифицированные новые карточки, включая сообщения без идентификатора.

Периоды: сегодня по часовому поясу браузера, последние семь или тридцать суток, собственный диапазон дат (обе даты включены), явный архив за всё время. Фильтр применяется к первоначальным датам публикаций и к доказательствам в карточке. Год CVE не используется как фильтр: старая уязвимость может обсуждаться или эксплуатироваться снова. Архив не означает актуальность сегодня. Даты загрузки и изменения записи не заменяют дату публикации. Счётчики публикаций, новостей, издателей и независимых материалов относятся к выбранному периоду. Есть поиск, регион/язык/издатель, основание и статус, сортировка и ширины колонок. «Тренд» рядом с CVE в существующих таблицах показывает текущий семидневный результат.

- Эксплуатация подтверждена: свежий факт из CISA KEV/MSRC либо проверенное аналитиком доказательство. Сам по себе PoC, патч, EPSS или ответ модели эксплуатацию не подтверждает.
- Независимые публикации: минимум две самостоятельные группы за выбранный период. Датированные материалы автоматически участвуют в оценке. Один издатель, совпадающий текст или прямая ссылка на другую публикацию об этой CVE объединяют материалы. Общая справочная ссылка на NVD, CVE или бюллетень производителя сама по себе не делает новости перепечатками. Значимые параметры URL сохраняются; метки отслеживания удаляются. Это автоматическая оценка самостоятельности, а не доказательство эксплуатации. Аналитик может переопределить решение; комментарий без изменения решения его не сбрасывает.
- Исходная дата публикации определяет окно. Обновление страницы, первый импорт старого KEV и переподключение не делают событие новым. При отсутствии даты сигнал остаётся на проверке. Тренд истекает, когда необходимое доказательство выходит из семидневного окна; отзыв пересчитывает основание.

CVE/GHSA извлекаются правилами, статья может относиться к нескольким идентификаторам. Сообщение без идентификатора попадает в ранние сигналы; аналитик связывает его с CVE/GHSA, решение сохраняется с автором, датой и версией публикации. Подтверждение конкретной версии не переносится автоматически на изменённый текст. Ручные связи и история решений сохраняются при полном восстановлении.

При настроенной общей LLM и разрешении источника выполняется русская выжимка, выделение продукта/версий и цитаты. Машинное утверждение не становится доказательством. Проверяется JSON-схема и наличие цитаты в оригинале. Ошибка модели не мешает доставке и точным совпадениям; анализ повторяется при следующем получении. Без модели работают правила и ручная проверка.

Точные совпадения — текущие `VmHostCve` и `VmImageCve`, поэтому очередной локальный импорт виден без нового события сборщика. У образа видны пакет, установленная/исправленная версия и дата скана. Подсказки по названию продукта/ОС выводятся отдельно как кандидаты: версия и наличие уязвимости не подтверждены. Отсутствие совпадений не доказывает отсутствие проблемы: проверяйте дату импорта и покрытие сканирования. Сырые тексты и URL не исполняются; ссылки открываются только HTTP(S).

## Доставка и восстановление

`GET /api/v1/info` возвращает protocol_version=1, collector_id, epoch, last_seq и scopes. `GET /api/v1/changes?after=N&until=M&limit=100` отдаёт последовательный журнал с неизменной верхней границей M; `next_cursor` сохраняется в одной транзакции с событиями. Повтор страницы идемпотентен, изменившееся повторное событие или пропуск отклоняются. Ограничение страницы 500 событий / 8 MiB. Журнал и версии сохраняются без автоматической очистки, следите за диском.

Изменение collector_id/epoch останавливает обычное получение. Полную синхронизацию явно запускают в настройках. Новое поколение становится видимым после полной доставки и анализа правил; старые публикации и ручные решения не удаляются. На старте незавершённая доставка догоняется очередным pull, полностью принятые публикации анализируются фоново.

`stools-threat-collector backup --output /data/backup.db` создаёт согласованный SQLite snapshot. Для restore остановите сервер, выполните `restore --output /data/backup.db` (здесь output — путь читаемой копии), затем запустите его. Restore меняет epoch. Telegram-файлы копируются отдельно при остановленном клиенте.

`stools-threat-collector export --after N --output /data/updates.zip` готовит резервный пакет `manifest.json` + `pages.jsonl` с SHA256. Загрузка в настройках STools использует тот же приёмник; до применения проверяются состав, контрольная сумма и последовательность. Лимиты: 100 MiB архив, 500 MiB распакованные данные, 8 MiB страница. Пакет не имеет цифровой подписи: передавайте его доверенным каналом. Неполные пакеты/архивы с лишними файлами отклоняются. После смены epoch администратор включает флажок полного восстановления перед загрузкой ZIP: используется `/import/full`, принимающий только пакет с `after=0`. Старое поколение остаётся видимым до завершения анализа.

## API и права

STools: `/api/vm/trends` (список); `/{id}` (карточка); `/{id}/matches`; `/{id}/review` (PATCH с версией); `/badges?ids=...`; `/status`; `/sync`; `/sync/full`; `/import` (multipart file); `/settings` (GET/PUT); `/settings/test`; `/sources` (GET/POST); `/sources/{id}` (PATCH); `/sources/{id}/collect` (POST). Коллектор: `/api/v1/info`, `/sources`, `/sources/{id}`, `/sources/{id}/collect`, `/jobs/{id}`, `/changes`. Токен только в Authorization Bearer. Health `/health/ready` доступен без токена и не отдаёт данные.

Право чтения VM — просмотр; запись VM — ручное получение, импорт и решения аналитика; администратор VM — соединение, источники и полная синхронизация. Конфликт версии карточки или источника возвращает 409, перезагрузите данные перед повтором.

## Исправление разбора новостей и источников

RSS/Atom сохраняет CVE/GHSA, ссылки и первоначальную дату анонса при обогащении полным текстом. HTML-парсер выбирает тело статьи и удаляет связанные материалы, боковые блоки и навигацию. Отсутствующая дата остаётся неизвестной, если у самой статьи нет проверяемой даты публикации; дата обновления не подставляется вместо неё. Старые материалы и будущие даты не становятся свежими сигналами.

Checkpoint RSS содержит `parser_version=2`: при первом сборе старой версии условные заголовки игнорируются, затем снова применяются ETag/Last-Modified. Исправленная публикация сохраняется новой ревизией; исходная история не переписывается. Повторное чтение исправляет записи, ещё присутствующие в ленте. Материалы, уже исчезнувшие из RSS, автоматически не восстанавливаются из несуществующего архива.

KEV — запись каталога эксплуатации, а не новостная статья. Ссылка ведёт на CISA с фильтром конкретной CVE; отдельно доступны справочные ссылки. Первоначальная `dateAdded` сохраняется при обновлении парсера. Старые KEV-записи видны в архиве и не заполняют свежие периоды без новых доказательств.

Отклонённые и отозванные материалы остаются в карточке в пределах выбранных дат для аудита и возврата решения, но исключены из квалификации и счётчиков действующих доказательств. Поэтому число строк доказательств может превышать число учитываемых публикаций.


## Мониторинг источников, Telegram и PoC

Каталог SOC сопоставлен с каталогом STools: 118 исходных строк, 164 уникальных конечных источника. Предпросмотр изменений сохраняет ручные интервалы и enabled; добавления выключены. Telegram web не требует сессии; существующий MTProto сохраняется.

Классификация relevant/early_signal/background/uncertain и роли primary/actionable/mentioned сохраняют причины. Метаданные CVE и PoC доставляются отдельными сущностями v2 и не считаются новостями. CVE-контекст NVD/CNA/EPSS хранит происхождение и состояние провайдеров; точный сканерный матч не отменяется эвристикой версии. GitHub candidate/likely — статическая оценка одной SHA; confirmed/rejected — локальное решение аналитика.

Операции, лимиты, переключение v2 и откат описаны в [trend-monitoring-operations.md](trend-monitoring-operations.md).


### Помощь при чтении CVE и публикаций

`POST /api/vm/trends/{id}/assistant` (роль VM analyst/write) принимает `mode=translate|explain`, для публикации — `publication_key` и `revision` вместе. Произвольный текст клиентом не передаётся. Задача `vulnerability_assistant` назначается в общих настройках ИИ отдельно от `threat_analysis`; общий выключатель и ограничения local_only/data_class сохраняются. Публичные материалы Telegram доступны только для явного ручного запроса; прежний фоновый путь их не обрабатывает. Ручной запрос не зависит от llm_allowed: этот флаг продолжает управлять только фоновым threat_analysis, ручной вызов его не изменяет.

Контекст содержит только описание/публичные показатели CVE и разрешённые тексты, без хостов, образов и заметок. Если есть описание CVE, обе команды используют его и показатели этой CVE без примешивания новостей о других уязвимостях. Если описания нет, подбор исключает rejected/suppressed/background, добирает данные порциями и ограничивается тремя материалами. В summary проверяется целевая CVE; неожиданные другие CVE отклоняются (502). Перекрёстные ссылки, уже присутствующие в исходном описании CVE, разрешены. Это предотвращает перенос показателей между случайно связанными новостями. Прямой разбор публикации может обсуждать все CVE из её текста. Прямой разбор исключённой публикации включает только код её статуса. Ревизия и принадлежность публикации проверяются до запроса. Успешный ответ сохраняется для обработанного содержимого до повторной проверки: при изменении текста возвращается stale, при неактуальной ревизии возможен 409, но оплаченный ответ остаётся в базе. Обновление служебных дат не делает результат устаревшим. Ошибки провайдера и неверный JSON дают безопасное 502. Результат хранится отдельно в vm_trend_ai_answer и не меняет доказательства/риск/статусы. GET /{id}/assistant восстанавливает перевод и объяснение без обращения к модели, POST повторно использует точный сохранённый ответ. Ключ зависит от целевого материала, режима и фактического содержимого, без модели/генерации сборщика/времени обновления кэша. Изменение текста помечает прежний результат устаревшим, обновление запускается явно. PostgreSQL advisory lock объединяет конкурентные запросы одинакового результата; ожидание и сохранение используют одну выделенную связь с БД, без транзакции во время обращения к модели.

В карточке сохранённый перевод показывается на месте исходного описания CVE или текста публикации. «Показать оригинал» / «Показать перевод» переключают язык без запроса к модели. Отдельного блока «Перевод на русский» нет. Сохранённое «Объяснение ИИ» раскрыто сразу и отображается независимо от языка текста. Для публикации автоматически раскрывается её область текста с переводом. Читатели без права генерации по-прежнему видят исходный текст и могут читать сохранённые ответы.
