# Эксплуатация мониторинга CVE

## Границы

Сборщик опрашивает внешние источники. STools получает данные по HTTPS (по умолчанию 8443), напрямую либо через свой HTTP/HTTPS CONNECT proxy. Сборщик не подключается к STools. Во внешние API передаются публичные CVE и ID репозиториев, не инвентарь и не результаты сканирования.

Источники, интервалы и флаги обогащения общие для потребителей сборщика. Решения PoC, исключения и локальные совпадения хранятся в STools. Получение использует существующую задачу `trends_pull` общей страницы расписаний; планировщик Threat Hunting не меняется.

## Перенос каталога

В каталоге 164 записи. Manifest сохраняет соответствия всех 118 строк SOC, включая aliases и retired/replaced. Новые источники выключены. Предпросмотр не записывает конфигурацию. Применение проверяет revision всего каталога; массовая операция также проверяет version каждой строки. Дубли URL и неразрешённые конфликты отвергаются атомарно.

CSV/XLSX: до 5 MiB и 5000 строк; поля name, url, adapter, publisher_id, language, region, content_scope, importance, interval_minutes, enabled, telegram_mode, telegram_channel, fallback_urls. Формулы не исполняются. Экспорт содержит whitelist публичных параметров без секретов и proxy profiles. Ошибки строк отображаются до применения.

## Доступ и доверенные CA

`COLLECTOR_HTTP_PROXY` и `COLLECTOR_CA_FILE` задают маршрут по умолчанию. `COLLECTOR_REQUIRE_PROXY=true` запрещает прямой доступ при отсутствии прокси. Дополнительно `COLLECTOR_OUTBOUND_PROFILES_FILE` указывает JSON-файл вида:

```json
{"corporate":{"proxy_url_file":"/run/secrets/corporate-proxy","ca_file":"/run/secrets/corporate-ca.pem","required":true}}
```

Источник выбирает `inherit`, `direct` либо имя профиля. При обязательном proxy вариант direct отвергается. Профили и secret refs монтируются администратором развёртывания; UI получает только имена и готовность. TLS verification не отключается. GitHub token при наличии читается из `COLLECTOR_GITHUB_TOKEN_FILE`. Секреты не входят в CSV, журнал задач или публикации.

## Запуски и пределы

Одновременно работают до четырёх источников, запросы к одному домену последовательны. Telegram web читает до трёх страниц за порцию с паузой 2–5 секунд; позиция продолжения отдельна от окончательного watermark. Первый проход ограничен 30 днями, последующие сверяют семь дней и непрочитанные ID после перерыва. Смена разметки — ошибка, отсутствие поста в окне — не удаление. Изменённый текст создаёт ревизию того же permalink.

После ошибок: 5/15/60 минут, после пятой — системная пауза с probes 6/12/24 часа; Retry-After может увеличить задержку. Пользовательский enabled не меняется. Успешный сбор снимает системную паузу.

SourceRun показывает fetched/new_versions/classification counters, coverage, continuation, stage и ошибку без секретов. Проверка preview сохраняет до десяти образцов текста, не добавляя публикации. Повторный CollectionWindow и возобновление старой задачи изолированы от основного checkpoint. Отмена проверяется под блокировкой и внутри транзакции записи порции. При смене конфигурации старая задача не возобновляется.

RSS даёт только текущую ленту; произвольный период не обещает полного архива. NVD проходит фиксированное окно изменений с пагинацией и сохраняет исходную дату публикации. Обновление метаданных старой CVE не делает её свежей новостью.

Обогащение хранит очереди, кэш и ошибки каждого провайдера; EPSS обновляется раз в сутки. Поиск PoC обрабатывает до 20 репозиториев за порцию и продолжает страницы; новый цикл не чаще шести часов. Предел GitHub Search 1000 результатов отражается как ограниченная выдача. Общая квота API учитывает Retry-After и rate-limit reset. Статическая проверка читает до 50 текстовых файлов и 2 MiB, привязанных к одной SHA. Код, зависимости и workflow не исполняются.

## Миграция v1 → v2

1. Зафиксировать версии образов, compose chain, миграцию PostgreSQL, collector ID/epoch/seq, source ID/checkpoint и числа публикаций/решений. Сделать защищённые snapshots PostgreSQL и SQLite.
2. Проверить миграцию на копии. PostgreSQL `c83f0e4a921d` добавляет таблицы metadata/PoC/review/policy. SQLite миграция добавочная; существующий Telegram без mode остаётся MTProto.
3. Обновить STools, принимающий v1/v2. Проверить v1 pull. Затем обновить collector; enrichment/PoC по умолчанию выключены, protocol остаётся v1.
4. Проверить совместимость всех зарегистрированных потребителей. Только после этого вызвать `Store.enable_protocol_v2()` административной командой на сборщике. Все отложенные сущности публикуются без пропуска; повторный вызов идемпотентен.
5. Применить просмотренный каталог и включить необходимые задачи. Наблюдать cursor, pending analysis, состояния провайдеров и реальные публикации. Не считать недоступный источник успешным.

Один возврат старого образа не является проверенным откатом: его Alembic может не знать новую revision, даже если схема добавочная. Для образов до `c83f0e4a921d` использовать согласованный snapshot PostgreSQL, collector SQLite и соответствующие старые образы; восстановление сначала проверять на отдельной базе. После записи v2 старый consumer не подключать к живому журналу. Полный откат требует согласованных snapshots PostgreSQL/SQLite и образов; новые публикации и решения после snapshot сначала экспортируются отдельно для повторного применения. Архивы не удаляются.

## Ожидаемые ограничения

Отсутствие EPSS/PoC или ошибка провайдера не равны нулевому риску. Для Harbor импорт сейчас не содержит vendor/ecosystem: совпадение пакета остаётся кандидатом unknown. Неполная CPE-логика, маркетинговые и backport-версии не дают автоматического «не затронуто». Точное совпадение CVE в сканере сохраняется независимо от внешних диапазонов.

Доступность — доля успешных проверок за показанную историю (последние 200 запусков), релевантность — отдельный счётчик. Локальные совпадения доступны в карточках CVE. Каталог может содержать отключённые, заменённые или недоступные в данном контуре источники; их состояние явно видно.
