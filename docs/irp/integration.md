# Интеграция STools с IRP

STools остаётся источником учётных записей и ролей. Уровень IRP задаётся в
матрице роли в настройках доступа. Встроенный администратор получает
`admin`. Аналитики, аудиторы и существующие пользовательские роли начинают
с `deny`. Для перехода из меню приложений нужен как минимум `read`.

IRP проверяет сессию через `GET /api/integrations/irp/v1/session`,
передавая только сессионную cookie STools. Имя cookie на обеих сторонах
должно совпадать. Значение по умолчанию — `stools_session`. Каталог
`GET /api/integrations/irp/v1/users` доступен с уровнем `write` и возвращает
активных исполнителей. Поле `truncated` показывает, что остались другие
исполнители.

`POST /api/integrations/irp/v1/enrichment` принимает до 20 сущностей.
Для включения передайте `STOOLS_IRP_SERVICE_TOKEN` только серверным
процессам STools и IRP. Разрешённые источники укажите через запятую в
`STOOLS_IRP_ENRICHMENT_SCOPES`. По умолчанию список пуст. Запросы читают
локальные данные и не запускают импорт или синхронизацию.

| Область | Данные |
| --- | --- |
| `assets` | Карточка актива по имени хоста, точному FQDN или IP. |
| `accounts` | Учётная запись инвентаря по SAM, UPN или полному имени. |
| `av` | Состояние защиты хоста по последнему снимку каждого сервера KSC. |
| `vm` | Хост и до 20 связанных CVE, начиная с наибольшего риска. |
| `attack` | Связи CVE хоста с техниками ATT&CK из локального справочника. |

Точное совпадение может дать несколько карточек. В этом случае ответ
содержит `ambiguous`. Для доменов поиск выполняется по точному FQDN,
а инвентари v1 не предоставляют поиск по хешам.

Для общей точки входа Caddy маршрутизирует `/irp/*` в
`STOOLS_IRP_WEB_UPSTREAM` (по умолчанию `irp-web:80`) и
`/api/irp/*` в `STOOLS_IRP_API_UPSTREAM` (по умолчанию `irp-api:8000`).
Оба адреса должны быть доступны контейнеру `web`. IRP разворачивается
отдельно. Если IRP ещё недоступен, маршруты STools продолжают работать.


## Локальный стенд

Общий вход — `http://localhost:8080/`, IRP — `http://localhost:8080/irp/`.
Меню приложений открывается нажатием на щиток. У пользователя должна быть
выдана область IRP; глобальный администратор получает её автоматически.
Сессия STools используется без повторного входа.

IRP запускается из отдельного репозитория `hamster513/irp` через
`compose.prod.yml`, со своей базой и сетью `stools_default`. В локальном
`.env` IRP заданы текущие образы стенда, адрес API STools, общий сервисный
токен и `IRP_PUBLIC_ORIGIN=http://localhost:8080`. Подробные инструкции
развёртывания и API находятся в репозитории IRP.

Для обновления этого экземпляра STools используется локальный,
исключённый из Git файл `ops/.env.irp-stand.yml`. Он сохраняет параметры
текущего экземпляра и выбранные теги образов:

```sh
docker compose --env-file ops/.env -f ops/docker-compose.yml \
  -f ops/.env.irp-stand.yml up -d --no-build --no-deps api web
```

Предыдущие образы и настройки сохранены для отката в локальном
`ops/.env.irp-rollback.yml`; резервная копия БД — в `ops/.env.irp-backups/`.
Эти файлы содержат локальные параметры и не публикуются.
Учебный экземпляр IRP с синтетическими источниками остаётся на порту 8091;
его данные и авторизация отделены от общего стенда.
