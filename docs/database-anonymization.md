# Обезличивание полного бэкапа PostgreSQL

`ops/stools_db_anonymize.py` обрабатывает собственный доверенный бэкап STools внутри периметра: запускает отдельный PostgreSQL, восстанавливает исходную БД, переносит все строки с заменами, делает новый бэкап и проверяет его настоящим восстановлением. Затем удаляет временный контейнер вместе с томом. Рабочая БД и исходный файл не изменяются.

**Соответствия «что → на что» хранятся в отдельном JSON-конфиге.** Конфиг, исходный дамп и исходный ключ шифрования не включаются в результат. Скрипт не отправляет данные во внешние сервисы. Временный PostgreSQL запускается без сети и опубликованных портов, без подключения файлов хоста и Docker socket. Docker-логирование для него отключено, чтобы не использовать возможный внешний сборщик логов хоста.

## Требования и границы

- Python 3.7.3+, Docker CLI и работающий Docker. Скопируйте вместе четыре файла из `ops`: `stools_db_anonymize.py`, `stools_db_clone.py`, `stools_db_masking.py`, `stools_db.py`.
- Вход: каталог бэкапа `stools_db.py` с `manifest.json` и `database.dump` либо отдельный custom dump `pg_dump -Fc`. Plain SQL, tar/directory dump и физическая копия `PGDATA` не поддерживаются.
- Нужен **заранее загруженный локальный образ** PostgreSQL той же основной версии и с нужными locale/расширениями. Скрипт использует `--pull=never`. Для каталога версия берётся из manifest; для отдельного файла по умолчанию PostgreSQL 16. Проверено на PostgreSQL 16; принимаются версии 15+ при совпадении версии источника. Для другой версии/сборки укажите `--postgres-image`. Encoding и locale сохраняются из manifest либо из описания создания БД внутри отдельного дампа; если описание прочитать нельзя, обработка останавливается. Поддержаны провайдеры locale libc и ICU.
- Свободное место: исходный дамп, две развёрнутые БД, новый дамп, WAL и место для построения индексов. Ориентируйтесь на размер развёрнутой базы, а не сжатого архива. Нужен также запас памяти под крупнейшее JSON/XML-значение; таблицы переносятся потоком, не целиком в память.
- Это копия **всех данных PostgreSQL**, без сокращения истории и количества строк. Физический размер файлов и сжатого архива изменится: строки обезличиваются, индексы строятся заново.
- Файлы `/data` API и SQLite коллектора не входят в дамп PostgreSQL. Если снимок AD/KSC ссылается на исходную выгрузку в `/data`, без этого файла повторный анализ может быть недоступен. Не добавляйте необезличенный `api-data.tar.gz` к результату.

Обезличивание определяется вашим конфигом: скрипт не угадывает все фамилии, названия компаний, номера телефонов и внутренние адреса. Укажите варианты написания, DNS/NetBIOS/DN, логины, ФИО, хосты и другие необходимые значения. Неизвестные произвольные закодированные данные в обычном тексте автоматически не декодируются. Перед выносом копии проверьте полноту правил внутри периметра. Проверка восстановления подтверждает целостность базы, а не полноту обнаружения персональных данных.

## Отдельный конфиг замен

В репозитории есть только вымышленный пример: [stools_db_anonymize.example.json](../ops/stools_db_anonymize.example.json). Рабочий конфиг держите вне Git и каталога результата, с правами `600`:

```bash
umask 077
mkdir -p "$HOME/stools-private"
cp ops/stools_db_anonymize.example.json "$HOME/stools-private/anonymize.json"
chmod 600 "$HOME/stools-private/anonymize.json"
```

Отредактируйте эту копию под свои данные. Пример структуры:

```json
{
  "format": "stools-db-anonymize/1",
  "case_sensitive": false,
  "replacements": [
    {"from": "corp.example", "to": "lab.example"},
    {"from": "DC=corp,DC=example", "to": "DC=lab,DC=example"},
    {"from": "alice", "to": "person-0001"}
  ],
  "networks": [
    {"from": "10.10.0.0/16", "to": "10.200.0.0/16"}
  ]
}
```

`replacements` — буквальные подстроки, не регулярные выражения. Более длинная замена имеет приоритет; замены выполняются за один проход, без цепочек. Псевдонимы должны быть уникальными, отсутствовать в исходных данных и не содержать ни одного `from`. Используйте достаточно конкретные значения: замена короткого общего слова может задеть структуру или смысл правила. Не меняйте технические коды, операторы, версии ПО и имена структурных полей. Следите за максимальной длиной столбцов.

По умолчанию регистр учитывается; в примере `case_sensitive: false`. DNS-домен и LDAP DN — разные строки, поэтому для них нужны отдельные записи. SID/UUID и другие идентификаторы сохраняются; если их тоже нужно скрыть, добавляйте согласованные явные замены, сохраняя допустимый формат идентификатора.

Для IP используйте `networks`: IPv4/IPv6, одинаковая длина префикса у `from` и `to`. Для одного адреса задайте `/32` или `/128`. Сохраняются смещения адресов, размеры подсетей и диапазонов. Исходные сети не должны перекрываться друг с другом; целевые — тоже. Если широкий диапазон невозможно перенести без изменения его смысла, скрипт остановится. Целевые подсети выбирайте свободными от других исходных объектов.

В тексте бюллетеней GitHub Advisory Database (поля `summary` и `description` таблицы `public.vm_ref_ghsa`) широкий диапазон IPv4 сохраняется, если обе его границы лежат вне всех сетей `from` и `to`. Упоминание такого диапазона допускается, даже если он охватывает одну из настроенных сетей. Явно указанные IP, подсети CIDR и имена в том же тексте обрабатываются по конфигу. В политиках, активах и структурированных данных JSON/XML действуют полные проверки диапазонов.

В JSON/XML значения меняются с сохранением структуры и типов; числа, логические флаги, порты и версии ПО сохраняются. Поддержаны массивы PostgreSQL и двоичные IP `octets` в KSC. Конфликт уникальности, сломанная ссылка, неоднозначная замена или изменение SQL-схемы останавливают обработку. Конфиг без единого совпадения тоже не даст готовый результат.

## Запуск внутри периметра

Заранее подготовьте образ, если его ещё нет (загрузка образа не требует доступа к бэкапу):

```bash
docker pull postgres:16-alpine
```

Проверьте `docker context show`: временные ресурсы создаются на выбранном Docker-хосте. Выполните из корня проекта, подставив свои пути:

```bash
python3 ops/stools_db_anonymize.py /secure/production-backup \
  --config "$HOME/stools-private/anonymize.json" \
  --output /secure/anonymized-backup \
  --postgres-image postgres:16-alpine
```

Первым аргументом можно передать `/secure/database.dump`. Выходной каталог должен быть новым и находиться отдельно от исходного бэкапа. Его перезапись запрещена.

Если есть сохранённые зашифрованные исходные конфигурации «Радара», потребуется `cryptography` в Python, которым запускается скрипт, и исходный `STOOLS_SESSION_SECRET`. `cryptography` уже есть в окружении API STools. Для старого хоста без совместимой версии библиотеки используйте современное отдельное окружение Python внутри периметра; совместимость Python 3.7 относится к самому скрипту без этой дополнительной библиотеки. Передайте ключ **через окружение, не аргументом командной строки**. Пример для Bash с вводом без отображения и сохранения в истории:

```bash
read -r -s -p 'Исходный STOOLS_SESSION_SECRET: ' STOOLS_SOURCE_SECRET
export STOOLS_SOURCE_SECRET
python3 ops/stools_db_anonymize.py /secure/production-backup \
  --config "$HOME/stools-private/anonymize.json" \
  --output /secure/anonymized-backup \
  --source-secret-env STOOLS_SOURCE_SECRET
unset STOOLS_SOURCE_SECRET
```

Не присылайте ключ в чат. Исходные конфигурации расшифровываются в памяти, обезличиваются и шифруются новым ключом; контрольная сумма содержимого «Радара» пересчитывается. При отсутствии/неверном ключе обработка остановится. Для неизвестного зашифрованного содержимого, непрозрачного `bytea`/KSC binary, large objects, секционированных/внешних таблиц, наследования, materialized views и неподдерживаемых типов SQL/ARRAY скрипт также останавливается: молчаливого удаления или копирования таких данных нет.

## Что получится и как загрузить на стенд

После успеха новый каталог имеет права `700`, файлы — `600`:

| Файл | Содержание |
|---|---|
| `database.dump` | Полная обезличенная БД в формате `pg_dump -Fc` |
| `manifest.json` | Версия/locale PostgreSQL, размер и SHA-256; совместим с `stools_db.py` |
| `anonymization.json` | Счётчики строк по таблицам, выполненных замен и проверок; только SHA-256 конфига, без соответствий |
| `stand.env` | Новый `STOOLS_SESSION_SECRET` для сохранённых зашифрованных конфигураций |

Перед публикацией результата сравниваются схема, количество строк в каждой таблице и состояния последовательностей, проверяются FK/unique/check-ограничения. Новый дамп действительно восстанавливается ещё раз. Результат публикуется после удаления временного PostgreSQL и тома; manifest появляется последним.

Пароли/API-ключи интеграций сбрасываются, действующие сессии становятся недействительными, пользователи приложения отключаются. Общие расписания, ночной запуск Threat Hunting и известные автоматические интеграции отключаются; незавершённые задания общей очереди отменяются. **Пользователи Assets, членства в группах, настройки и флаги политик AD/KSC сохраняются.** Соль ключей находок SIEM сохраняется, чтобы не потерять связи с решениями аналитиков. Роли/SQL-grants исходного PostgreSQL-кластера не переносятся, как и при обычном восстановлении `stools_db.py`.

На стенде используйте [инструкцию восстановления](database-backup.md#восстановление): сохраните текущую БД, остановите приложения и восстановите новый каталог командой `stools_db.py restore`. Для этой копии задайте API **новый ключ из `stand.env`**, а не продовый ключ. Затем создайте новую локальную учётку администратора, например:

```bash
docker exec -it stools-api-1 python -m api.cli create-user stand-admin --group 'Администраторы'
```

Пароль вводится интерактивно. Настройки подключений проверьте перед повторным включением расписаний. Исходную копию и рабочий конфиг оставьте внутри периметра.

## Прерывание и ошибки

Если скрипт остановился на коллизии, посмотрите последнюю ошибку. В ней указаны схема и таблица, столбец, номер строки в потоке COPY и целочисленный `id`, если такой столбец есть. Нумерация строк начинается с 1 и относится к текущему запуску. Внутри JSON скрипт показывает путь к полю. Например, `$.hosts[2].ip` означает поле `ip` третьего элемента массива. Произвольные имена ключей представлены как `[#N]` — номер поля в объекте при чтении, начиная с 1. Для SQL-массивов сохраняются их исходные индексы.

Указатель `networks[0].to` относится к целевой подсети первой записи в массиве `networks` вашего конфига. Если адрес из дампа уже входит в эту подсеть и ни одно правило `from` его не переносит, для `to` нужна свободная подсеть той же длины префикса. Чтобы увидеть сам IP (либо CIDR, границы диапазона) и пару сетей конкретного правила, добавьте к своей команде `--show-conflicting-ips`, сохранив остальные параметры:

```bash
python3 ops/stools_db_anonymize.py /secure/production-backup \
  --config "$HOME/stools-private/anonymize.json" \
  --output /secure/anonymized-backup --show-conflicting-ips
```

Флаг выводит адреса в stderr. Храните такой вывод внутри периметра. При совпадении текстового псевдонима скрипт указывает запись `replacements[N].to` в исходном порядке конфига. Строка БД, содержимое поля, исходные логины и текстовые замены скрыты в обоих режимах.

При ошибке, Ctrl+C или SIGTERM скрипт удаляет только собственные контейнер и том по уникальной метке `stools.db-anonymize.job`. SQL-ошибки и строки данных не выводятся. Код `0` — готовый проверенный результат, `1` — ошибка, `130` — отмена.

При выключении Docker/компьютера или SIGKILL автоматическое удаление невозможно. Скрипт не утверждает, что очистка выполнена, если Docker недоступен. После восстановления Docker проверьте оставшиеся ресурсы:

```bash
docker ps -a --filter label=stools.db-anonymize.job
docker volume ls --filter label=stools.db-anonymize.job
```

Удаляйте только ресурсы завершённого/прерванного запуска, сверив имя и метку. Временная папка `.stools-anonymize-*` рядом с результатом имеет права `700`; после аварийного завершения её также нужно проверить и удалить. Отсутствие `manifest.json` означает незавершённый результат. Исходный бэкап и конфиг скрипт не удаляет.

Формат custom archive и восстановление параметров создания БД описаны в документации PostgreSQL: [pg_dump](https://www.postgresql.org/docs/16/app-pgdump.html), [pg_restore](https://www.postgresql.org/docs/16/app-pgrestore.html).
