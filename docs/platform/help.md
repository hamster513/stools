# Справка

Встроенная справка объясняет, что такое STools, что показывает каждая страница
и как её настроить, а также сами понятия предметной области (техника ATT&CK,
балл домена, EPSS). Работает без сети и без сервера: статьи лежат в коде
фронтенда как markdown-файлы и уезжают в бандл. Отдельного API и таблиц в базе
у справки нет. Раздел и панель открыты любому вошедшему пользователю, уровень
доступа для них не нужен; какие действия доступны на странице, статья
описывает словами по уровням.

## Что видит пользователь

- **Пункт «Справка по странице»** в меню пользователя: логин внизу рейки
  модулей — кнопка, по нажатию справа от неё всплывает маленькое меню
  (`platform/UserMenu.tsx`): подсказка по странице, тёмная или светлая тема,
  выход. При открытой панели пункт называется «Закрыть справку». Меню есть на
  всех страницах вошедшего пользователя (рейку и панель монтирует
  `components/layout/AppShell.tsx`); на экране входа его нет.
- **Панель подсказки** — справа, 400 px, без затемнения: страница под ней
  остаётся видна и кликабельна. Показывает короткую часть статьи текущей
  страницы: блок «Что это», «Что здесь можно» по уровням, чипы понятий и ссылку
  «Вся справка →». Содержимое следует за адресом: перешли на другую страницу —
  панель показывает её статью. Открытое состояние хранится в
  `sessionStorage['stools-help-open']` и переживает переходы между модулями, но
  не закрытие вкладки. Фокус при открытии уходит на заголовок панели, при
  закрытии возвращается на кнопку-логин в рейке. `Esc` закрывает панель первой (обработчик
  висит на `window` в capture-фазе и гасит событие), открытому дроверу или меню
  «Экспорт» нужен второй `Esc`. Любой переход из панели в раздел справки (чип
  понятия, ссылка `help:` в «Что это», «Вся справка →») закрывает панель. Пока
  панель уезжает при закрытии, в ней остаётся последняя статья; закрытая панель
  за адресом не следит.
- **Раздел «Справка»** — `/help` и `/help/:slug`; в него ведёт ссылка «Вся справка →» из панели подсказки, своего значка в рейке у раздела нет.
  Слева поиск и оглавление, справа статья: крошки, заголовок, строка
  «Где … · Кому …», блок «Что здесь можно» и текст. Кнопка «Открыть страницу →»
  показывается у статей модулей и настроек (не у «Начала» и словаря) и ведёт на
  первый шаблон из `routes` без `:` и `*`, кроме страниц создания `…/new`; нет
  такого шаблона — нет кнопки. Видна она, только если у пользователя хватает
  прав, и решает адрес цели, а не группа статьи (`help/core/open.ts`): адрес
  `/settings/<раздел>` — правило раздела `settingsNeed` из
  `platform/settings/pages.ts` (как в `SettingsShell`; `null` — открыт всем);
  страница модуля — наименьший заполненный уровень статьи в её `module`
  (`any` или `read` → аудитор, иначе `write` → аналитик, иначе администратор).
  `/help` без `slug` открывает статью `stools` без перенаправления;
  несуществующий `slug` даёт «Статья не найдена».
- **Поиск** — по заголовкам и тексту всех статей без учёта регистра и разницы
  «ё»/«е» (`fold` в `core/plain.ts`), до 20 результатов, совпадения в
  заголовке первыми, во фрагменте найденное подсвечено. `Enter` открывает первый
  результат, `Esc` очищает запрос. Пока в поле есть запрос, оглавление скрыто.

Оглавление (`toc()` в `help/index.ts`) состоит из четырёх групп: первая без
заголовка — «Что нового» (одна статья, см. ниже) и статьи `group: start`;
дальше «Модули» (модули со `status: 'available'` в `platform/modules.ts`, в
порядке рейки; права пользователя здесь не учитываются — оглавление у всех
одно), «Настройки», «Словарь». У статей первой группы в крошках нет звена
группы. Узел модуля ведёт на статью его корня (`/<модуль>`),
внутри — его статьи `group: module` по `order` и названию, затем его понятия.
Страница настроек модуля (`/settings/<модуль>`) — тоже `group: module`, её место
среди страниц модуля задаёт `order`. В группу «Настройки» попадают только
статьи `group: settings` (платформенные, `module: platform`).
Статьи платформенных настроек с общим `section` (сейчас «Доступ») собираются в
один узел, как вкладки в меню настроек.

## Где лежат статьи

`frontend/src/help/articles/<папка>/<файл>.md`; сейчас папки `start`, `module`,
`settings`, `glossary`. Статьи собираются обходом `articles/**/*.md`, поэтому
подпапки допустимы. Группу статьи задаёт поле `group`, а не папка: держите их
согласованными. Имя файла произвольное, статью идентифицирует `slug`. Сейчас
111 статей: «Что нового», 5 общих (`start`), 53 «Модули», 8 «Настройки», 44 «Словарь».

Ядро разбора и проверок — чистый TypeScript без React в `help/core/`
(`frontmatter.ts`, `match.ts`, `validate.ts`, `plain.ts`, `toc.ts`, `open.ts`, `types.ts`);
его используют и бандл, и скрипт проверки сборки.

## Формат статьи

Файл — фронтматтер между строками `---` и markdown-тело. Фронтматтер —
небольшое подмножество YAML, свой разбор в `core/frontmatter.ts`. Разрешено:
`ключ: значение` (с кавычками и без), `ключ: [a, b, "c d"]`, блок `levels:` с
отступом в два пробела, `#`-комментарии, пустые строки. Всё остальное
(вложенность глубже, табуляция, многострочные значения, неизвестный ключ,
повтор ключа) — ошибка с файлом и номером строки. `#` в начале строки или после
пробела вне кавычек начинает комментарий: значение без кавычек с « #» внутри
обрежется молча (`where: Модуль #1` → «Модуль»), такие значения берите в кавычки.

```markdown
---
slug: siem-rules
title: Инвентарь правил
group: module
module: siem
order: 3
routes: ["/siem/snapshots/:id/rules"]
where: Модуль SIEM → «Инвентарь правил»
levels:
  read: Смотреть правила и их карточки, фильтровать, экспортировать список.
  write: Выбирать и подтверждать техники ATT&CK для правила.
  admin: Отмечать в профиле инсталляции списки, от которых зависит колонка «Ограничено».
concepts: [correlation-rule, snapshot, technique]
---

## Что это

Все [правила корреляции](help:correlation-rule) выбранного [снапшота](help:snapshot) одним списком.

## Как читать

…

## Как настроить

…
```

| Ключ | Тип | Смысл |
|---|---|---|
| `slug` | строка, обязателен | идентификатор статьи и адрес `/help/<slug>`; уникален |
| `title` | строка, обязателен | заголовок в оглавлении, панели, поиске |
| `group` | `start` \| `news` \| `module` \| `settings` \| `glossary`, обязателен | группа оглавления |
| `module` | строка | id модуля или `platform`; обязателен у `module` и `settings`, у словаря необязателен (см. ниже) |
| `routes` | список шаблонов | адреса, для которых статья — «статья страницы» |
| `where` | строка | «Где» — путь в интерфейсе, строка «Где: … · Кому: …» |
| `levels` | блок `read`, `write`, `admin`, `any` | что можно делать на каждом уровне; «Кому» — наименьший заполненный уровень |
| `concepts` | список slug'ов словаря | чипы «Понятия» в панели |
| `order` | целое | порядок в группе или модуле; без него — после остальных, по названию |
| `section` | строка | узел оглавления в группе «Настройки», под который собираются статьи |

Что обязательно по группам (проверяет `core/validate.ts`):

| Группа | Поля | Разделы тела |
|---|---|---|
| `module`, `settings` | `slug`, `title`, `group`, `module` (id доступного модуля или `platform`), `routes` (не пусто), `where`, `levels` (хотя бы одна непустая строка) | `## Что это`, `## Как читать`, `## Как настроить` |
| `start`, `glossary` | `slug`, `title`, `group` | `## Что это` |
| `news` | `slug`, `title`, `group` | любые: по разделу `## <дата>` на выпуск |

Остальные разделы произвольны: у «Начала» это, например, «Из чего состоит» и «С
чего начать», у словаря — «Где встречается в STools». Раздел — это текст под
заголовком второго уровня; заголовки внутри кодовых блоков не считаются.
Панель показывает только `## Что это`, поэтому первый абзац должен читаться сам
по себе.

**Ссылки.** На другую статью — `[текст](help:<slug>)`; на страницу приложения —
`[текст](/siem/hygiene)`; внешние `https://…` открываются в новой вкладке.
Существование `help:<slug>` проверяется при сборке; адреса приложения `(/…)` с
`routes.json` не сверяются — опечатка в них проверку пройдёт. Адрес, который
начинается с `//` или `/\`, браузер понимает как чужой сайт: он выводится
простым текстом. Так же — `(#якорь)`, `mailto:` и любые другие схемы, кроме
`help:` и `http(s)`. Картинки `![…](…)` не выводятся вовсе. Только заголовки
`##` получают `id` (строчные буквы, пробелы в «-», знаки препинания
выбрасываются; у `###` `id` нет), и адрес `/help/<slug>#<id>` прокручивает
статью к заголовку; наличие такого `id` проверкой не контролируется.

**Уровни.** У модулей строки `read`, `write`, `admin` выводятся как «Аудитор»,
«Аналитик», «Администратор»; у статей с `module: platform` — как «Чтение» и
«Администратор» (названия уровней платформы из `platform/access/types`,
уровня `write` у платформы нет). Страница, открытая любому вошедшему
(профиль, «Статусы находок»), вместо уровней получает одну строку `any:`; она
выводится как «Все вошедшие». Уровни не показываются у `start` и `glossary`.

## Адреса и выбор статьи

Шаблон в `routes` разбирается по сегментам (`core/match.ts`), query и `#hash`
отбрасываются:

| Сегмент | Совпадает |
|---|---|
| `siem` | ровно с таким сегментом |
| `:id` (любое имя после `:`) | ровно один произвольный сегмент |
| `*` | любой хвост, включая пустой; допустим только последним сегментом |

Шаблон начинается с «/». `*` не в конце — ошибка проверки.

Для адреса побеждает шаблон с наибольшим числом литеральных сегментов; при
равенстве шаблон без `*` важнее. Если ни один шаблон не подошёл, берётся статья
корня модуля (в `routes` ровно `/<первый сегмент адреса>`), а если и её нет —
статья со `slug: stools`. Корневые статьи модулей обычно пишут пару
`["/siem", "/siem/*"]`: `*` ловит любую вложенную страницу без собственной
статьи, поэтому запасной вариант «корень модуля» срабатывает редко. Примеры из
текущих статей:

| Адрес | Побеждает | Почему |
|---|---|---|
| `/siem/snapshots/12/rules` | `/siem/snapshots/:id/rules` | три литерала против одного у `/siem/*` |
| `/ksc/servers/3/policies/7` | `/ksc/servers/:id/policies/:policyId` | у `/ksc/servers/:id/policies` другая длина, он не подходит |
| `/ad/domains/5/что-то-новое` | `/ad/*` | единственное совпадение, один литерал |
| `/help/ad-jobs` | `/help/*` (статья «Как пользоваться справкой») | `*` берёт хвост |
| `/xyz` | статья `stools` | запасной вариант «корень» |

Дубли шаблонов запрещены: `/ad/:id` и `/ad/:domainId`, `/ad/jobs` и `/ad/jobs/` —
один и тот же адрес в разных статьях. Одна статья может иметь несколько шаблонов
(например, список и карточка). В режиме разработки отсутствие своей статьи у
открытой страницы пишется в консоль: `[help] нет статьи для <адрес>` — только
пока панель справки открыта (статью страницы выбирает панель).

## Словарь

Статья словаря объясняет одно понятие, на него ссылаются из других статей.
Правила, принятые в существующих статьях:

- `module: <id>` ставится у понятия одного модуля — оно появится в оглавлении
  под этим модулем (после его страниц) и в общем «Словаре». Понятия,
  которые встречаются в нескольких модулях (находка, снапшот, уровень), идут
  без `module` и видны только в «Словаре».
- `routes: []`: у словаря своих страниц нет.
- Раздел `## Что это` — определение для человека, который видит термин
  впервые; в конце раздел `## Где встречается в STools` со списком статей
  страниц, где понятие встречается (ссылки `help:`). Проверка этого раздела не
  автоматизирована.
- При первом упоминании термина в другой статье ставится ссылка
  `[термин](help:slug)`. Понятия, важные для страницы, дублируются в её
  `concepts:` (они станут чипами в панели); каждый slug из `concepts` обязан
  быть статьёй группы `glossary`.

## Инвентарь адресов и покрытие

`frontend/src/help/routes.json` — плоский список адресов приложения, как их
пишут в `routes` (`:id` для параметров). Это эталон «что в приложении есть»:
проверка требует, чтобы каждый адрес из него подошёл хотя бы под один шаблон
какой-нибудь статьи. Из него исключён модуль FW («в разработке»); справка не
описывает заглушки.

**Правило для нового кода: новая страница или вкладка — адрес в `routes.json` и
статья, у которой он указан в `routes` (или новый шаблон у существующей
статьи).** Без этого `npm run build` падает.

## Проверка: `check:help` и `test:help`

```bash
cd frontend
npm run check:help                 # разбор всех статей и правила; код 1 при ошибке
node scripts/check-help.ts --no-coverage   # то же без сверки с routes.json
npm run test:help                  # тесты ядра: node --test src/help/core/*.test.ts
```

`check:help` (`scripts/check-help.ts`) разбирает все `articles/**/*.md` и
печатает по строке «файл: сообщение». Проверяет: синтаксис фронтматтера;
обязательные поля и разделы по группам (таблица выше); что `module` у статей
модулей и настроек — id модуля со `status: 'available'` из
`src/platform/modules.ts` (список читается из файла как текст) или `platform`;
уникальность `slug`;
корректность шаблонов `routes` и отсутствие дублей между статьями; что каждая
ссылка `help:<slug>` в теле (вне кодовых блоков) ведёт на существующую статью;
что каждое понятие из `concepts` — статья словаря; покрытие `routes.json`.
Флаг `--no-coverage` отключает только последнюю проверку.

Та же проверка встроена в сборку двумя способами: `npm run build` начинается с
`npm run check:help`, а плагин `vite-plugins/helpCheck.ts` (в `vite.config.ts`
с `coverage: true`) повторяет её в `buildStart`. Сборка падает со списком
ошибок, пока справка не в порядке; образ не соберётся с битой статьёй.

`test:help` гоняет `node --test` по `src/help/core/*.test.ts` (конфиг типов —
`tsconfig.test.json`): разбор фронтматтера, сопоставление адресов, валидатор,
простой текст и сравнение для поиска, вложение `section` в оглавление, правило
кнопки «Открыть страницу →». Сменили правило в
`core/` — меняйте и тест.

## Правила для интерфейса новых страниц

Справка не занимает углов страницы: кнопки в правом верхнем углу страницы
никакого отступа под неё не требуют.

Слои по `z-index`:

| Слой | z-index |
|---|---|
| затемнение дровера, меню пользователя в рейке | 30 |
| дровер | 40 |
| модальное окно поверх дровера: портал KSC (объекты), подтверждения удаления в Assets | 50 |
| панель справки | 60 |

Новый дровер берёт слои 30/40, модальное окно поверх дровера — 50; 60 не
занимать.
Панель справки вне слоёв модальных окон: страница под ней кликабельна.

## «Что нового»

Одна статья `articles/news/news.md` (`group: news`, slug `news`), первая в
оглавлении. Раздел `## ДД.ММ.ГГГГ` на день, новые сверху: всё, что вышло за
сутки, дописывается в раздел текущего дня, сколько бы сборок ни было (решение
владельца 28.10.2026: один день — один раздел, иначе страница дробится на
мелкие записи). Теги сборок в статье не пишутся, они в журнале проекта.
Внутри раздела — «Добавлено», «Улучшено», «Исправлено» или подразделы по
модулям (`###`).

Правило выпуска: вместе с публикацией образа в раздел сегодняшнего дня (новый,
если его ещё нет) дописывается всё, что вошло в сборку со времени предыдущей.
Текст — на языке пользователя: что появилось, что стало лучше, что исправлено,
по модулям; без имён файлов и без данных заказчика.

## Как добавить статью

1. Новая страница приложения: добавьте её адрес в `frontend/src/help/routes.json`
   (список отсортирован по алфавиту).
2. Создайте файл в `articles/module/` (страница модуля), `articles/settings/`
   (настройки) или правьте существующий, если страница — вкладка той же статьи,
   и допишите шаблон в `routes`.
3. Заполните фронтматтер и три раздела: `Что это`, `Как читать`, `Как настроить`;
   уровни `read`/`write`/`admin` (или `any`) описывают, что на этой странице
   доступно на каждом уровне, по тому, как это устроено в коде и в
   `docs/platform/access.md`.
4. Термины при первом упоминании — ссылки `help:`; нет статьи для понятия —
   создайте её в `articles/glossary/` и добавьте в `concepts:` страницы.
5. Новое понятие одного модуля — `module: <id>`; общее — без `module`.
   Допишите страницу в раздел «Где встречается в STools» понятия, если оно
   теперь встречается и на ней.
6. Проверьте: `npm run check:help` без ошибок; `npm run test:help`, если
   правили `core/`; `npm run dev`, откройте страницу, в меню пользователя
   нажмите «Справка по странице» — должна
   открыться ваша статья, а не запасная (в консоли нет `[help] нет статьи для …`).
7. Тексты на русском, обращение на «вы», только вымышленные имена правил,
   хостов, доменов и цифры — реальные выгрузки в справку не попадают.

## Ограничения

- Поиск — вхождение подстроки без учёта регистра, без морфологии: «правило» не
  найдёт «правила». Ищется по заголовку и тексту без разметки; таблицы,
  списки и код входят в текст.
- Ссылки `(#якорь)` внутри статьи выводятся простым текстом, не ссылкой.
- В `npm run dev` плагин проверки выполняется при запуске сервера и при правке
  `.md` не перезапускается: запускайте `npm run check:help` вручную или
  смотрите на ошибки в консоли браузера.
- Картинок и видео нет: статьи только текстовые.
- Модуль FW не описан (заглушка «в разработке»); когда он появится, его адреса
  попадают в `routes.json` и получают статьи по общему правилу.
- Язык один — русский; текст не зависит от уровня доступа пользователя, права
  описаны словами внутри статьи.
