# Сборщик AD для доменной машины

Скрипт `STools-AD-Collector.ps1` (версия 2.0) скачивается в интерфейсе: Active Directory →
Настройки и данные → «Скачать». Он ничего не анализирует и не меняет в домене и пишет
файлы двух видов:

| Файл | Формат | Что внутри |
|---|---|---|
| `ad-<NETBIOS>-<дата>.json.gz` | `stools-ad/1` | выгрузка AD: учётные записи, группы, ACL, `GptTmpl.inf` политик из SYSVOL, шаблоны сертификатов, центры сертификации и контейнеры PKI, политики выдачи, доверенные домены |
| `adca-<NETBIOS>-<дата>.json.gz` | `stools-ad-ca/1` | данные ЦС: флаги и права центров сертификации, два значения реестра контроллеров домена, ответ веб-выдачи |

Данных ЦС в LDAP нет, и STools сам их не собирает — ни онлайн-сбором по LDAP, ни иначе.
Без файла данных ЦС проверки ESC6–8, 10, 11, 16 на обзоре помечены как «не проверено» — только
в доменах, где есть AD CS (в выгрузке AD есть шаблоны сертификатов или центр сертификации). В
домене без AD CS этим проверкам нечего проверять, и пометки нет.

## Требования

- Windows с PowerShell 5.1 или новее и модулем ActiveDirectory (RSAT).
- Скрипт хранится в UTF-8 с BOM: без него Windows PowerShell 5.1 читает файл в ANSI и ломает
  кириллицу в строках. При правке сохраняйте BOM (тесты `test_collector_script_has_utf8_bom`,
  `tests/ad/test_collector_script.py`).
- Права — по разделам, см. ниже.

## Меню

Без параметров (или только с `-Server` и `-Yes`) скрипт показывает меню:

```
1  Всё: выгрузка AD и данные ЦС (два файла)
2  Выгрузка AD полностью
3  Выгрузка AD без ACL компьютеров (быстрее)
4  Выгрузка AD без SYSVOL
5  Данные ЦС: настройки и права центров сертификации
6  Данные ЦС: реестр контроллеров домена
7  Данные ЦС: проверка веб-выдачи
Выбор (можно несколько через запятую, например 5,7):
```

Пункт 1 равен «2,5,6,7». Пункты 3 и 4 сочетаются (оба сокращения сразу), пункт 2 их исключает;
5–7 сочетаются между собой и с выгрузкой AD. На неверный выбор скрипт объясняет, что не так, и
спрашивает снова.

Затем скрипт печатает план — контроллер для запросов LDAP, какие центры сертификации,
контроллеры и адреса он опросит и что прочитает — и спрашивает «Продолжить? (y/n)».

## Параметры

| Параметр | Что делает |
|---|---|
| `-Mode Menu \| All \| AD \| CA` | `Menu` — меню и подтверждение; `All` — выгрузка AD и данные ЦС; `AD` — только выгрузка AD; `CA` — только данные ЦС. С `All`, `AD`, `CA` меню и вопроса нет — так скрипт запускается без участия человека. Без `-Mode` режим выбирается по остальным параметрам: `-SkipComputerAcl`, `-SkipSysvol` или `-OutputPath` — `AD` (команды сборщика 1.x вроде `-SkipSysvol -OutputPath x.json.gz` работают как раньше); `-Sections` — `CA`, а вместе с `-SkipComputerAcl` или `-SkipSysvol` — `All`; ничего из этого — `Menu` |
| `-Sections ca,dc,web` | разделы данных ЦС для `All` и `CA`; по умолчанию все три |
| `-SkipComputerAcl` | выгрузка AD без дескрипторов компьютеров (быстрее; проверка ACL компьютеров пуста) |
| `-SkipSysvol` | выгрузка AD без `GptTmpl.inf` (проверка User Rights Assignment пуста) |
| `-Server` | контроллер домена для запросов LDAP (по умолчанию — ближайший) |
| `-OutputPath` | файл или каталог. По умолчанию — текущий каталог. Каталог — оба файла в нём под именами по умолчанию. Файл — в него пишется выгрузка AD (или данные ЦС в режиме `CA`); если файлов два, данные ЦС ложатся в тот же каталог под именем по умолчанию |
| `-Yes` | в режиме меню не спрашивать подтверждение после плана |

```powershell
.\STools-AD-Collector.ps1                                        # меню
.\STools-AD-Collector.ps1 -Mode All -Server dc01.corp.local -OutputPath C:\Temp\
.\STools-AD-Collector.ps1 -Mode AD -SkipComputerAcl
.\STools-AD-Collector.ps1 -Mode CA -Sections ca,web
```

## Что читает каждый раздел и какие нужны права

| Раздел | Откуда | Права |
|---|---|---|
| выгрузка AD | LDAP контроллера домена; `GptTmpl.inf` из SYSVOL | учётная запись домена с правом чтения каталога (обычный пользователь читает дескрипторы большинства объектов; SYSVOL доступен всем доменным пользователям) |
| `ca` — настройки и права ЦС | `certutil -config "<сервер>\<ЦС>" -getreg` для `policy\EditFlags`, `policy\DisableExtensionList`, `CA\InterfaceFlags`; при отказе certutil — те же значения удалённым реестром. Права ЦС (`Security`) — всегда удалённым реестром (`HKLM\SYSTEM\CurrentControlSet\Services\CertSvc\Configuration\<ЦС>`). Сборка ОС — из объекта компьютера ЦС в AD | администратор ЦС или локальный администратор сервера ЦС; на сервере ЦС запущена служба «Удалённый реестр» (Remote Registry) |
| `dc` — реестр контроллеров | удалённый реестр каждого контроллера (`Get-ADDomainController -Filter *`): `HKLM\SYSTEM\CurrentControlSet\Services\Kdc\StrongCertificateBindingEnforcement` и `HKLM\SYSTEM\CurrentControlSet\Control\SecurityProviders\Schannel\CertificateMappingMethods`; отсутствующее значение пишется как `null`. Единственный раздел, который обращается к контроллерам не по LDAP | чтение удалённого реестра контроллеров (обычно — администратор домена или делегированное право на эти ключи) |
| `web` — веб-выдача | запрос `GET` без учётных данных и без перенаправлений (таймаут 10 с) к `http://<ЦС>/certsrv/`, `https://<ЦС>/certsrv/` и адресам из `msPKI-Enrollment-Servers`; записываются код ответа и схемы из `WWW-Authenticate` | сетевой доступ к серверам ЦС по портам 80 и 443 |

Ошибка по отдельному серверу (нет прав, служба не запущена, сервер недоступен) пишется в поле
`error` записи этого сервера и не прерывает сбор; скрипт показывает её предупреждением. В
раздел `sections` файла попадают только запрошенные разделы.

Выгрузка AD несёт в `collector.notes` то, что сборщик не прочитал: предупреждения сбора (например,
отказ доступа к контейнерам PKI, `CN=OID` или доверенным доменам) и «чтение SYSVOL выключено
(-SkipSysvol)», если SYSVOL пропущен. Причину пропуска SYSVOL обзор показывает в «не проверено» у
User Rights Assignment.

## Ход работы и отказы

У каждой строки хода работы — время от начала сбора `[мм:сс]` и счётчики по шагам. Если сбор
оборвался, скрипт называет шаг и строку скрипта, печатает стек и говорит, какие файлы успели
записаться.

## Что дальше

Загрузите файлы в STools по одному: Active Directory → Настройки и данные → «Загрузить
выгрузку» — одно и то же поле для обоих видов, формат определяется по содержимому. Выгрузка AD
даёт снапшот домена; данные ЦС сохраняются отдельно для домена (домен ищется по SID, поэтому
сначала загрузите выгрузку AD) и пересчитывают последний снапшот. Для анализа берутся самые
свежие данные по каждому разделу.

Оба файла содержат инвентарь домена и настройки инфраструктуры — обращайтесь с ними как с
чувствительными данными.

Онлайн-режим (сбор из STools по LDAP) даёт ту же выгрузку AD — проверки в обоих режимах одни и
те же; данные ЦС в онлайн-режиме не собираются.
