# kbaudit

Ядро модуля SIEM Rules Analyzer (STools): разбор выгрузки базы знаний MaxPatrol SIEM и поиск
средовых значений, зашитых в правила. Работает без базы данных, без HTTP
и без доступа в сеть.

## Установка

```bash
cd backend
python3 -m venv .venv
./.venv/bin/pip install -e ".[dev]"
```

## Использование

CLI даёт четыре команды: `stats`, `findings`, `divergence`, `verify`.

```bash
./.venv/bin/kbaudit stats "../knowledgebase_2026_08_21 [Acme].zip"
```

Сводка по выгрузке: число правил, групп `type_id`, рёбер графа зависимостей,
клонов, распределение находок по классам и полярности, состояние критичных
табличных списков. `--json` — машиночитаемый вывод (без самих находок,
правил, каталога и расхождений — только агрегаты).

```bash
./.venv/bin/kbaudit findings "../выгрузка.zip" --kind 1 --limit 20
```

Список находок: по правилу, полю, полярности и принадлежности табличному
списку. `--kind` фильтрует по классу 1..5, `--limit` — сколько строк
показать (по умолчанию 40).

```bash
./.venv/bin/kbaudit divergence "../выгрузка.zip" --limit 30
```

Расхождения «правило ↔ табличный список»: значение зашито в правиле и
одновременно живёт в табличном списке — два источника истины, которые
могут разойтись. Показывает, где именно зашито значение и сколько правил
это затронет. `--limit` — сколько строк показать (по умолчанию 30).

```bash
./.venv/bin/kbaudit verify "../выгрузка.zip" --expected tests/fixtures/reference_numbers.json
```

Сверка агрегатов отчёта с эталонным JSON. При расхождении — ненулевой код
возврата и построчный список несовпавших полей; удобно для CI.

### Значения находок скрыты по умолчанию

Значения находок и расхождений — это адреса, имена хостов и учётные
записи, то есть инвентарь инфраструктуры. Команды `findings` и `divergence`
по умолчанию заменяют их непрозрачным порядковым номером (`<скрыто> #N`):
одинаковые значения получают один номер, разные — разные, но по номеру
восстановить исходное значение нельзя (нумерация не хеш и не переживает
следующий вызов команды). Чтобы увидеть настоящие значения, нужен явный
флаг `--show-values`.

## Тесты

```bash
./.venv/bin/pytest
```

Регрессионные тесты требуют настоящую выгрузку и без неё пропускаются:

```bash
export STOOLS_FIXTURE_ZIP="../knowledgebase_2026_08_21 [Acme].zip"
./.venv/bin/pytest
```

Эталонные числа выведены из самой выгрузки и в репозитории не лежат:
положите их рядом с архивом в файл `<имя архива>.numbers.json` (для
примера выше — `knowledgebase_2026_08_21 [Acme].zip.numbers.json`). Без
него проверка чисел пропускается. Если тест не сошёлся, чинить парсер,
а не подгонять число.

### База для тестов HTTP-слоя

Тесты `tests/api`, `tests/vm`, `tests/ad`, `tests/attack_module` ходят в
Postgres — тот же, что в проде: SQLite прощает то, чего сервер не прощает
(переиспользование id, наивные datetime, отсутствие длин у varchar), и
зелёный прогон на нём ничего не говорил о работе на стенде. Базу тесты
поднимают сами: один контейнер `postgres:16-alpine` на весь прогон pytest,
схема раскладывается `alembic upgrade head`, между тестами таблицы
чистятся `TRUNCATE`. Нужен только работающий docker; наборы без базы
(`tests/analyzers`, `tests/parsers`, `tests/attack`) контейнер не трогают.

Если сервер уже есть (CI, стенд разработчика) — указать его в
`STOOLS_TEST_DATABASE_URL`, тогда свой контейнер не поднимается:

```bash
STOOLS_TEST_DATABASE_URL=postgresql+psycopg://user:pass@localhost:5432/stools_test \
  ./.venv/bin/pytest
```

База должна быть одноразовой: миграции и `TRUNCATE` применяются к ней как
к своей.

## Запуск API вручную

Сам сервис тоже рассчитан на Postgres — умолчание `STOOLS_DATABASE_URL`
указывает на `postgresql+psycopg://kbaudit@localhost:5432/kbaudit`.
База из `ops/docker-compose.yml` наружу не публикуется (порт 5432 виден
только внутри сети стека), поэтому для запуска вне контейнера нужен свой
сервер, а его адрес задаётся переменной:

```bash
STOOLS_DATABASE_URL=postgresql+psycopg://kbaudit:pass@localhost:5432/kbaudit \
  ./.venv/bin/alembic upgrade head
STOOLS_DATABASE_URL=postgresql+psycopg://kbaudit:pass@localhost:5432/kbaudit \
  ./.venv/bin/uvicorn api.main:app --reload
```

## Разработка

Перед каждым коммитом:

