## Что это

Откуда реестр [активов](help:asset) берёт данные и по каким порогам считает [расхождения](help:discrepancy): синхронизация с модулями VM, Антивирус и AD, DNS-серверы, подключения RackTables и справочник [групп сетей](help:network-group). Страница открыта аналитику и администратору модуля, аудитор её не видит.

## Как читать

Блоки сверху вниз: «Пороги и автосинхронизация», «Синхронизация с модулями», «DNS», «RackTables», «Группы сетей». Аналитик видит пороги и группы сетей серыми, у DNS и RackTables — только таблицу источников с кнопкой «запустить», у синхронизации — кнопку «Обновить сейчас» и ссылку на расписание. Выключенный источник помечен «выключен» или «выключено» и не запускается ни кнопкой, ни по расписанию.

Периодичность синхронизации активов, каждого DNS-сервера и подключения RackTables задаётся в разделе [Расписание](help:sync-schedules). Подключение появится там после сохранения.

## Как настроить

### Пороги и автосинхронизация

[Открыть](/settings/assets#rules). «Устаревание, дней» (30): значение источника старше актуального на столько дней — «данные устарели», моложе — «источники расходятся»; 0 — любое отличие считается устаревшим. «Неактивность AD, дней» (30): компьютер AD без входа и без других источников дольше — «неактивный компьютер AD», с входом не старше — ему нужен агент антивируса. Флажок «Синхронизировать сразу после импорта в модулях VM, антивирус и AD» (включён). Расхождения считаются при чтении, поэтому новые пороги действуют сразу.

### Синхронизация с модулями

[Открыть](/settings/assets#sync). Время последней синхронизации и таблица по источникам: сколько хостов источник видит, сколько пропало и от какого числа данные. У VM это время импорта, у Антивируса и AD — время сбора [снапшота](help:snapshot). «Обновить сейчас» запускает синхронизацию, её ход — на странице [Задачи](help:assets-jobs).

### DNS

[Открыть](/settings/assets#dns). Режим «запросы к серверу»: сервер (имя или адрес, пусто — системный резолвер), прямые запросы (A и AAAA по известным именам обновляют IP активов) и обратные (PTR по известным адресам даёт имена хостам, известным только по адресу). Режим «зоны AD через LDAP»: подключение модуля AD, список зон по одной на строку и флажок «Читать зоны». Записи хостов из интегрированных в AD зон становятся [наблюдениями](help:observation) источника DNS, в том числе записи хостов, которых другие источники не видят; служебные записи и псевдонимы без адреса пропускаются. Зоны читаются с паузами между запросами, заданными в подключении AD. Ещё «Запросов в секунду» (1–1000, по умолчанию 50) и «Таймаут, мс» (100–30000, по умолчанию 3000). На имя уходят два запроса, на адрес — один; задача пишет оценку длительности.

### RackTables

[Открыть](/settings/assets#racktables). Подключение к JSON API RackTables: адрес `json_api.php` (например `https://racktables.example.local/json_api.php`), учётная запись AD с правом просмотра, пароль (хранится зашифрованным; пусто — оставить прежний), «Запросов в секунду» (1–100, по умолчанию 10; запросы идут строго по одному), «Таймаут, мс» (1000–120000), «Проверять сертификат TLS», «Включено». «проверить» спрашивает версию API.

Проход создаёт или обновляет [сети](help:assets-networks) с названием, VLAN и тегами; сеть, описанная вручную с тем же CIDR, остаётся вашей. Адрес с именем становится наблюдением источника RT, адрес без имени не переносится. В сетях шире /16 адреса не запрашиваются. Объекты RackTables не переносятся: API не отдаёт их привязку к адресам.

### Группы сетей

[Открыть](/settings/assets#zones). Справочник групп: имя, название, описание, расположение (внутренняя, DMZ, внешняя), «из интернета», «конфиденциальные» и число сетей. Сразу заведены DMZ, Internal, Guest, Management, Industrial и External. Признаки показываются у сетей и активов и работают как фильтры, в расчёт риска VM не идут. Группу, заданную у сетей или в [правилах групп](help:zone-rule), удалить нельзя. Сами правила — на странице [Сети](help:assets-networks).
