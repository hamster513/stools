## Что это

Все [правила корреляции](help:correlation-rule) выбранного [снапшота](help:snapshot) одним списком. Отсюда начинается разбор: по пометке «Внимание» видно, с каким правилом что-то не так, а щелчок по строке открывает карточку правила.

## Как читать

**Колонки.** Имя правила; автор; категория и группа (из имени правила по схеме именования); число msgid (идентификаторов событий); «Внимание»; первая [техника](help:technique) ATT&CK с [тактикой](help:tactic) и «+N», если техник больше; «Ограничено» — правило работает только по содержимому списка, отмеченного в [профиле инсталляции](help:installation-profile); «В SIEM» — установлено ли правило. Последняя колонка заполнена только у снапшота, собранного по API: в архиве этих сведений нет, там прочерк. Границы колонок можно перетаскивать.

**Пометка «Внимание»:**

- «Не разобрано» — тело правила не разобралось, и [находок](help:finding) по нему нет не потому, что всё хорошо.
- «Разобрать» — есть открытые находки высокой тяжести.
- «Посмотреть» — есть открытые находки средней или низкой тяжести.
- «Чисто» — открытых находок нет.

Щелчок по пометке открывает [находки этого правила](help:siem-hygiene).

**Значок у техники ATT&CK**: галочка — подтверждено человеком, искра — предложено моделью и ещё не проверено.

**Отбор.** Поиск по имени, галочки «требуют внимания» и «только ограниченные списком», кнопки разметки: вся, предложено, подтверждено, не размечено. Кнопка «Фильтры» открывает панель с авторами и категориями, а у снапшота из API ещё «В SIEM» (установлено или нет), наборы установки и папки. Выбранное в закрытой панели видно чипами. Справа счётчик «показано из всего»; при фильтре по разметке — ещё число групп. «Экспорт» сохраняет список с теми же отборами в CSV или XLSX.

**Карточка правила** выезжает справа:

- «Что обнаруживает» — описание из локализации выгрузки.
- Автор, категория и группа, итог разбора, ограничено ли списком; у снапшота из API — установка, папка и наборы установки.
- ATT&CK — техники с тактиками и обоснованием. Плашка «Разметка группы, для правила не уточнялась» значит, что техники достались от группы целиком.
- msgid — собственные и унаследованные («← унаследован»).
- Зависимости — родительские и дочерние правила.
- «Что не так с правилом» — замечания по классам с объяснением и советом и поля, в которых найдены значения; ссылка «Разобрать со значениями» открывает находки.
- Тело правила: значения из замечаний подсвечены цветом класса, отсутствующие и пустые табличные списки — волнистой чертой.

## Как настроить

Аналитик правит разметку кнопкой «Поправить» или «Уточнить для правила» в блоке ATT&CK карточки: ищет технику по названию или идентификатору и нажимает «Подтвердить разметку». Разметку групп целиком делают на странице [Разметка ATT&CK](help:siem-attack).

Колонка «Ограничено» и часть пометок зависят от [профиля инсталляции](help:siem-profile), который меняет администратор модуля. Сведения об установке появляются, когда снапшот собран из MaxPatrol в [настройках модуля](help:siem-settings).

### Полное исправление с ИИ

В карточке нажмите **«Предложить исправление с ИИ»** (нужны права записи SIEM). Модель получает полный исходник, описание, замечания с их значениями и статусами, имена зависимых правил и состояние используемых списков. Тела зависимостей и содержимое списков не передаются.

Предложение содержит **полный код**, **пояснения** с влиянием на срабатывания и **сравнение** с исходником: слева удалённые строки, справа добавленные. Отдельно перечислены нужные изменения списков и зависимостей, сценарии проверки и предположения. Код можно скопировать целиком.

Предложение сохраняется для версии исходника и контекста анализа. После изменения контекста старый результат скрывается как устаревший. Повторная генерация заменяет его только после успешного ответа; при ошибке прежний результат сохраняется. Одновременно выполняются не более двух генераций на процесс API и одна для конкретного правила.

**Это предложение для проверки аналитиком.** STools проверяет формат, завершённость ответа и сохранение объявлений, но не компилирует XP и не доказывает эквивалентность логики. Перед применением проверьте зависимости, компиляцию и срабатывания на положительных, отрицательных и граничных событиях. Исходное правило и SIEM автоматически не изменяются.

В [настройках ИИ](help:llm) задайте локальную Ollama и модель задачи **«Исправление правил SIEM»**. Внешние провайдеры для полного внутреннего исходника недоступны. Для этой задачи запрашивается контекст 65 536 токенов; локальному серверу нужна соответствующая память. Лимит исходника — 30 КБ и 2000 строк, всего контекста — 44 КБ. При превышении STools показывает ошибку, не обрезая правило. Тайм-аут задаётся в настройках задачи.
