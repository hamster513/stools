## Что это

Откуда модуль берёт данные о серверах Kaspersky Security Center (KSC) и по каким порогам их проверяет. Данные попадают двумя путями: файлом от скрипта, который запускают на машине внутри сети, или сбором по подключению прямо из STools. Оба дают одну и ту же выгрузку, каждая становится [снапшотом](help:snapshot) своего сервера. Страница открыта аналитику и администратору модуля, аудитор её не видит.

## Как читать

Блоки сверху вниз: скрипт, загрузка выгрузки, подключения к KSC, пороги проверок. У аналитика пороги показаны списком без полей, а из кнопок подключений есть только «собрать».

## Как настроить

### Скрипт для машины внутри сети

Кнопка «Скачать STools-KSC-Collector.ps1». Скрипт запускают на Windows с PowerShell 5.1 и новее (или на любой ОС с PowerShell 7) с доступом к серверу KSC по порту 13299, от учётной записи KSC с правом чтения. Он ничего не меняет и пишет один файл `.json.gz`:

`.\STools-KSC-Collector.ps1 -Server ksc01.example.local -User audit -Internal`

`-Internal` — внутренняя учётная запись KSC, без него — доменная с `-Domain`. Пароль скрипт спросит сам. Ещё параметры: `-Port`, `-OutputPath`, `-SkipTlsCheck` (самоподписанный сертификат сервера), `-SkipProducts` (быстрее, но без продуктов и компонентов по хостам), `-SkipPolicyContents` (без содержимого [политик](help:av-policy) и их [профилей](help:av-profile)). Параметры, пароль и секрет второго фактора можно держать в файле: шаблон создаёт `-InitConfig`, запуск по нему — `-ConfigPath`, удалить файл после сбора — `-DeleteConfigAfterRun`. Если на сервере включена двухэтапная проверка, скрипт спросит код. В файле выгрузки инвентарь устройств — обращайтесь с ним как с чувствительными данными.

### Загрузить выгрузку

[Открыть](/settings/ksc#upload). Перетащите файл `.json` или `.json.gz` в зону. Сервер определяется по имени из выгрузки, новый сервер заводится сам; снапшот сравнивается с предыдущим по времени сбора. Повторная загрузка того же файла даёт второй снапшот. Ход загрузки — в зоне и на странице [Задачи](help:ksc-jobs).

### Подключения к KSC (онлайн-режим)

[Открыть](/settings/ksc#connections). STools читает KSC сам по Open API — программному интерфейсу сервера KSC (HTTPS, порт 13299). Нужен сетевой доступ от сервера STools к KSC и учётная запись с правом чтения. Пароль хранится в базе и наружу не показывается.

Поля: название, сервер KSC, порт (по умолчанию 13299), учётная запись, пароль (при правке пусто — оставить прежний; если меняете сервер, порт, учётную запись, домен или флажки учётной записи и сертификата, пароль нужно ввести заново), домен — для доменной учётной записи. Флажки: «Внутренняя учётная запись KSC», «Проверять сертификат» (выключайте только для внутреннего центра сертификации, которому сервер STools не доверяет), «Собирать содержимое политик» (без него нет настроек, замков, профилей, [исключений](help:av-exclusion) и сетевых правил, зато файл меньше).

Кнопки в строке: «проверить» — пробное подключение; «собрать» — сбор сейчас, нужен сохранённый пароль; «расписание» — интервал от 1 до 720 часов и необязательное окно «с — по». Если в это время идёт другая задача модуля, запуск откладывается; без пароля расписание выключается. После первого сбора у подключения появляется пометка «сервер связан».

### Пороги проверок

[Открыть](/settings/ksc#rules). Меняет только администратор модуля: «Сохранить» и «Сбросить к умолчаниям».

- **Пороги в днях**: агент молчит (7), базы устарели (3), нет полного поиска (30), лицензия истекает (30), задача обновления не запускалась (7), зависла перезагрузка (7), сертификат истекает (60).
- **Доли**: провалы задачи, с которых [находка](help:finding) высокая (0,2), мало замков в политике (0,5).
- **Содержимое политик, максимум** — сколько политик читает онлайн-сбор (200).
- **Allowlist хостов** — маски имён (`test-*`, `*.lab.example.local`); находки по ним понижаются до «справочно».
- **Административные роли KSC** — какие роли считать административными.
- **Каталоги с правом записи пользователя, расширения исполняемых файлов, интерпретаторы** — по ним ищутся опасные исключения.
- **Ключевые компоненты политик KES** (Kaspersky Endpoint Security) — выключенный в политике компонент или его признак «включён» без замка дают находку.
- **Ключевые компоненты** — подстроки имён компонентов на хосте для проверки «Выключен ключевой компонент».

Пороги и списки действуют на новые выгрузки. Чтобы применить их к старым, пересчитайте снапшоты на странице [Снапшоты](help:ksc-snapshots).
