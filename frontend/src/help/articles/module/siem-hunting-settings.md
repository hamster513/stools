## Что это

Отдельная страница параметров Threat Hunting. Сохранение — кнопкой «Сохранить настройки Threat Hunting». Расписание и очередь хантов остаются в [Планировщике](help:siem-hunting-scheduler).

## Как читать

Сначала — ссылка на общее подключение MaxPatrol, затем параметры выполнения хантов, папка фильтров и срок хранения событий. Аналитик может читать настройки; изменяет их администратор SIEM.

## Как настроить

### Подключение

Rules Analyzer и Threat Hunting используют общее подключение MaxPatrol. Ссылка «Настроить подключение к MaxPatrol» открывает [форму подключения](/settings/siem#kb). Изменение сервера или API-токена применяется к обоим разделам.

### Выполнение и хранение

[Открыть](/settings/siem-hunting). Своя кнопка «Сохранить настройки Threat Hunting». Время старта, интервал и очередь [хантов](help:hunt) — в [Планировщике](help:siem-hunting-scheduler).

- **Ночной прогон**: таймаут запроса (300 с), график повторов упавшего запроса — минуты ожидания через запятую, сколько чисел, столько повторов (10, 20, 30, 30, 30, 30, 30), предел длительности ночи (20 ч), лимит событий на запрос без собственного лимита (5000; настраивается от 1 до 100 000).
- **[Большой хант](help:deep-hunt)**: горячие сутки (7), размер куска (3 ч), пауза между кусками (5 с), глубина по умолчанию (3 мес).
- **Хранение событий** (180 суток): старше удаляются, [находки](help:finding) и решения по ним остаются.

В скобках — значения по умолчанию.

### Фильтры событий Threat Hunting

В блоке Threat Hunting выберите существующую папку MaxPatrol и сохраните настройки. «Обновить» перечитывает доступные папки. Каталог для набора хантов показывает дерево выбранной папки и всех её вложенных папок. Папки можно раскрывать и сворачивать. Поиск по части или полному имени фильтра либо папки не учитывает регистр и лишние пробелы; ветки с совпадениями раскрываются автоматически. Выбор фильтров сохраняется при поиске и сворачивании. Флажок папки выбирает все её фильтры вместе с подпапками, включая скрытые поиском. Каждый выбранный фильтр добавляется отдельным запросом; уже добавленные в хант фильтры не дублируются. Пока каталог загружается, отображается сообщение о загрузке.

Создание и обновление фильтров в SIEM выполняется только вручную кнопкой у сохранённого запроса, большого ханта или находки. Сохранение ханта, импорт YAML и запуск ханта не публикуют фильтры. Прежняя настройка автосоздания больше не используется, даже если была включена.

Name запроса — имя фильтра SIEM. Description — локальное описание в STools; оно не отправляется в SIEM. Для публикации нужны права записи в выбранную папку. Повторная публикация использует прежний ID; при смене папки перемещение происходит только после нажатия кнопки. После смены сервера старые ссылки не используются.

Ошибки соединения показываются как невозможность проверить доступность, а не как отсутствие фильтра. Каталог для проверки карточки кэшируется на 30 секунд; «Проверить в SIEM» и обновление списка перечитывают его сразу.

Лимит относится к общему количеству сохраняемых событий одного запроса, а не к размеру страницы SIEM. Приложение читает страницы до этого предела. Собственный лимит в запросе имеет приоритет. Изменение применяется только к новым запускам.

### Материалы из интернета

В блоке **Материалы для Threat Hunting** скачайте автономный `download-intel.py` и запустите на компьютере с интернетом. Нужен Python 3.11 или новее; сторонние библиотеки не нужны. В Windows можно использовать `python` вместо `python3`.

```sh
python3 download-intel.py --output hunting.zip
```

Перенесите ZIP в сеть со STools и нажмите **Импортировать архив**. Импорт доступен администратору SIEM. Интернет на сервере STools не нужен.

Скрипт содержит RSS/Atom новостей и отчётов из общего каталога источников и репозитории [SigmaHQ](https://github.com/SigmaHQ/sigma) и [Elastic Detection Rules](https://github.com/elastic/detection-rules). Правила сохраняются в исходных YAML/TOML с версией репозитория и лицензией; преобразование в PDQL и автоматический запуск не выполняются.

| Параметр | Назначение |
|---|---|
| `--list-sources` | Показать идентификаторы источников |
| `--only sigmahq,elastic` | Скачать только выбранные источники |
| `--days 30` | Новости за последние 30 дней (по умолчанию) |
| `--days 0` | Все записи, которые доступны в текущих лентах |
| `--articles` | Дополнительно скачать текст HTML-статей; медленнее |
| `--max-per-source 200` | Предел новостей из одного источника |
| `--sources sources.json` | Заменить встроенный список своим JSON-списком |
| `--workers 4`, `--timeout 20` | Параллельность и таймаут сетевого запроса |

Прокси берётся из `HTTPS_PROXY`/`HTTP_PROXY`, доверенный CA — из `SSL_CERT_FILE`. Токены, внутренние данные и доступ к STools скрипту не нужны. Каталог встроен в скрипт; повторное скачивание обновлённого скрипта обновляет и каталог.

RSS показывает доступное окно публикаций, а не всю историю сайта. Без `--articles` сохраняется текст из ленты, который может быть сокращён издателем. Публикации без даты сохраняются с соответствующей отметкой. Вложения и PDF не скачиваются. Репозитории правил загружаются независимо от `--days`.

Результат каждого источника записывается в архив. Код завершения `0` означает полный сбор, `2` — частичный сбор с пригодным для импорта архивом, `1` — ошибку без готового архива. Недоступный источник не выдаётся за пустой успешный. Существующий файл архива не перезаписывается. Если превышен размер, ограничьте список через `--only` и соберите несколько архивов.

Каталог также открыт в меню **Threat Hunting → Материалы** всем пользователям с чтением SIEM; загрузка архива остаётся доступной только администратору. После импорта доступны поиск по заголовку/тексту/CVE/технике, фильтр «Новости и отчёты» или «Правила», исходный текст, ссылка на публикацию, версия репозитория и лицензия. Кнопка **Скачать текст** сохраняет исходный YAML/TOML или новостной текст. Проверяйте применимость и условия лицензии перед использованием правил.

Повторная загрузка не создаёт копии. Более старый архив не заменяет свежие материалы, а отсутствие записи в новом архиве не удаляет её. Сводка показывает добавленные, обновлённые, неизменившиеся и устаревшие записи; результаты источников раскрываются отдельно. Материалы не изменяют библиотеку хантов, правила SIEM или расписание.

Архив версии 1 содержит только `manifest.json` и `items.jsonl` с контрольной суммой SHA-256. Ограничения импорта: 64 МиБ ZIP, 128 МиБ распакованных материалов, 30 000 записей, до 1 МиБ текста на материал. Неподдерживаемый или повреждённый архив отклоняется целиком до записи.

Пример собственного источника:

```json
[{"id":"my-feed","name":"Мой источник","kind":"rss","url":"https://example.org/security/feed"}]
```
