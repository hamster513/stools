## Что это

Радар собирает сведения о пути к приложению. На первом этапе доступны конфигурации nginx: виртуальные серверы, URL, backend-серверы, локальные приложения, статические файлы и ограничения доступа. Модуль заменяет прежнюю заглушку FW.

Конфигурация не подтверждает внешнюю доступность. Сервисы с внешними и внутренними адресами показываются вместе; до сопоставления с внешними наблюдениями и сетевыми правилами доступ извне отмечен «Не установлен». ScanFactory пока не подключён. NetTrace отдельно рассчитывает сетевой участок; автоматическое соединение его результата с маршрутом nginx пока не выполняется.

## Как настроить

В «Настройки → Радар» выберите сразу несколько файлов **имя-сервера.conf**, нажмите «Предварительный просмотр», проверьте результаты и ограничения, затем «Сохранить снимки». Поддерживается полная текстовая выгрузка `nginx -T` с разделителями `# configuration file …:`. Include раскрываются только из присутствующих в выгрузке файлов. STools не обращается к файловой системе nginx и не выполняет конфигурацию.

Лимиты: 32 файла в пачке, 2 МиБ на файл и 16 МиБ на пачку. Текст — UTF-8. При ошибке любого файла пачка не сохраняется; предыдущие снимки остаются доступны. Повторная загрузка текущего неизменившегося файла не создаёт снимок. Если настройка сложна настолько, что превышен лимит раскрытия, импорт отклоняется с объяснением.

Оригинал хранится зашифрованным штатным ключом STools. Для восстановления базы вместе с оригиналами необходим прежний `STOOLS_SESSION_SECRET`. В интерфейсе показано ограниченное представление директив: комментарии, произвольные значения, значения заголовков и тела ответов скрыты. Это представление нельзя использовать для восстановления рабочего nginx.

## Как читать

Найдите сервер по имени, домену, адресу или backend. Откройте снимок и выберите виртуальный сервер.

- **Маршруты:** сворачиваемые записи location с назначением и настройками; `(server)` — контекст сервера, а не дополнительный URL. Вложенные location сохраняют путь родительских блоков.
- **Настройки:** явно заданные и унаследованные директивы с файлом и строкой источника. Неуказанные значения nginx по умолчанию не подставляются.
- **Связи:** схема выбранного маршрута слева направо. Она показывает один конфигурационный участок nginx → backend, а не полный вычисленный сетевой путь. Все члены upstream показываются с их параметрами; `down` не означает активное соединение.
- **Источники:** структурированное представление директив с поиском и номерами строк исходных файлов.
- **История:** последние 50 снимков; при открытии старого снимка показываются именно его настройки.

`localhost` и loopback относятся к серверу из имени файла. Совпадение с Assets показывается только при наличии права чтения Assets и одном точном совпадении имени/FQDN. По коротким именам разных доменов автоматическое объединение не выполняется.

Время импорта не равно времени сбора. Переменные в backend, отсутствующие include, контексты stream/mail и условные переходы отмечаются как ограничения. Парсер не вычисляет обработку произвольного HTTP-запроса, DNS, сетевую доступность или возможность эксплуатации CVE.

## Доступ

Для существующих пользовательских ролей доступ к новому модулю по умолчанию закрыт. Администратор выдаёт необходимые права области «Радар» через настройки доступа.


## Подключение NetTrace

Администратор «Радара» открывает **Настройки → Радар → NetTrace**, вводит HTTPS-адрес без `/api/ext/v1` и ключ с правами `nat:read` и `path:evaluate`, включает подключение и сохраняет. Для внутреннего центра сертификации добавьте CA в PEM. Проверка TLS обязательна. Ключ хранится зашифрованным и не возвращается в интерфейс. При смене адреса нужно ввести ключ заново либо удалить старый.

«Проверить подключение» проверяет доступ к набору снимков, устройствам и NAT первого видимого устройства; право `path:evaluate` проверяется только при расчёте. Если устройств нет, проверить право `nat:read` этим способом нельзя.

«Синхронизировать» ставит сбор в общую очередь. Периодичность, время, дни недели и зависимости настраиваются в **Настройки → Расписание → Радар → NetTrace**. Планировщик Threat Hunting не изменяется. Кнопка постановки в очередь подтверждает приём задачи, а не окончание сбора. Статус и отмена доступны в общей панели очереди.

Сохраняются устройства, интерфейсы, правила и публикации NAT из области доступа ключа. При ошибке или смене снимков неполная выгрузка не заменяет предыдущую. Повтор неизменившегося набора обновляет время проверки без новой копии. Смена адреса, ключа, CA или включённости сбрасывает текущую выгрузку; прежние расчёты остаются в истории с отметкой старого подключения.

## Расчёт сетевого участка

На вкладке **Радар → NetTrace** найдите устройство, нажмите **Выбрать вход**, укажите имя входного интерфейса, IPv4 источника, IPv4 назначения, порт и TCP/UDP. Устройство можно задать вручную по UUID. Если устройство и интерфейс не заданы, вход определяет NetTrace. Предпочтительна явная точка входа. IPv6, CIDR, FQDN и исходный порт не поддерживаются.

Для участка nginx → backend нужен фактический IP исходящего соединения nginx. Адрес из `listen` автоматически не подставляется. Кнопка **Поставить расчёт в очередь** сохраняет запрос; вкладку можно закрыть и вернуться к истории. Расчёт можно отменить, пока он ожидает или выполняется.

У каждого результата показаны варианты пути слева направо: устройства, входные и выходные интерфейсы, пакет до/после, правила, NAT, маршруты и снимки. Сохраняются исходный запрос, полный ответ NetTrace и выбранный набор снимков. NetTrace не поддерживает повторный расчёт на историческом наборе: история STools показывает сохранённый результат.

Одинаковый запрос может использовать результат не старше 15 минут только при прежнем подключении и том же текущем наборе снимков. Это явно отмечается в результате. Перед и после расчёта STools проверяет набор, фактические снимки каждого шага и общий список снимков. При HTTP 409 или несогласованности выполняется один повтор. Если снимки снова не согласованы, путь не считается подтверждённым.

## Границы выводов NetTrace

- **Прямой путь разрешён по модели** — правила пропускают пакет до сети назначения. Это не проверка работающего сервиса, обратного пути, состояния соединения или возможности эксплуатации CVE.
- **Условно разрешён / недостаточно данных** — ограничения или неполнота не позволяют подтвердить весь участок. Исходный вердикт NetTrace показан отдельно от итога проверки STools.
- При трансляции портов порт после NAT может быть неизвестен; последующие шаги NetTrace могут оцениваться по исходному порту. Изменение только порта с прежним IP NetTrace не распознаёт. STools не связывает такой результат с приложением автоматически.
- Публикации NAT могут молча ограничиваться 64 адресами/портами; правила ограничивают раскрытые стороны 256 элементами с признаком усечения. Пустые публикации означают отсутствие только при статусе `ok`; `no_snapshot`, `no_topology`, `unsupported_platform` — отсутствие достаточных данных.
- Снимки устройств собираются в разное время, даже когда набор согласован. Время источника и время локальной проверки показаны отдельно.

Локальные ограничения сборщика: до 1000 устройств, 20 000 элементов одного списка, 8 МиБ на ответ, 16 МиБ на список и 64 МиБ на выгрузку. При превышении задача завершается ошибкой с сохранением прежней выгрузки. Запросы ограничиваются общей скоростью; HTTP 429 повторяется до трёх раз с учётом Retry-After.
