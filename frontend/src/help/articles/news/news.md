Что добавлено, улучшено и исправлено в STools, по дням: всё, что вышло за день, в одном разделе, самые новые сверху. Что такое STools целиком — [Что такое STools](help:stools).

## 27.11.2026

- **Обезличивание бэкапа.** Широкий диапазон IP в тексте бюллетеня GHSA больше не прерывает обработку, если обе его границы лежат вне сетей из конфига. Явно указанные внутренние адреса в том же тексте заменяются по правилам.

## 26.11.2026

- **ПО: поиск по диапазону версий.** После поиска по названию можно выбрать «Выше» или «Ниже» и указать версию. Счётчики и хосты в правой панели учитывают только подходящие установки. Числовые части сравниваются по значению: `2.10` выше `2.9`, а `2.10.0` равна `2.10`. Пустые версии и версии с буквами исключаются из сравнения. [Каталог ПО](help:assets-software).
- **Объединение записей хостов.** Аналитик может объединить карточки одного устройства с разными именами из RackTables, KSC, AD и других источников. Наблюдения, связи пользователей и групп сохраняются в общей карточке; доменное имя из AD имеет приоритет, а закреплённые вручную значения сохраняются. [Карточка хоста](help:assets-list).
- **Все IP-адреса хостов из MaxPatrol VM.** Новый импорт забирает основной адрес и адреса интерфейсов, включая IPv6. Они видны в карточке Assets и участвуют в поиске. Для появления дополнительных адресов нужен новый сбор MaxPatrol и синхронизация Assets. [Настройки VM](help:vm-settings).
- **Почта и руководитель из AD.** LDAP- и PowerShell-сборщики передают почту и руководителя пользователя. Поля доступны в списке, карточке, поиске и экспорте; руководитель открывается ссылкой, если его карточка найдена однозначно. Для новых данных нужен повторный сбор и синхронизация; для офлайн-сбора — обновлённый скрипт. [Пользователи](help:assets-users).

- **Обезличивание полного бэкапа PostgreSQL.** Отдельный скрипт восстанавливает копию в изолированном временном контейнере и применяет внешний конфиг «что → на что». Сохраняются строки, связи и настройки политик; перед выдачей нового бэкапа проверяется его восстановление. Конфиг соответствий остаётся внутри периметра, временный контейнер и том удаляются. При конфликте видны таблица, столбец, строка и правило конфига. Флаг `--show-conflicting-ips` показывает конфликтующий IP и пару подсетей внутри периметра.

## 23.11.2026

- **SBOM хоста.** ПО из MaxPatrol и KSC сгруппировано по названию. Для одной сборки видны оба источника и переданные ими версии. Если на хосте несколько версий или архитектур пакета, их можно раскрыть в строке. [Карточка хоста](help:assets-list).
- **Уязвимости пакетов РЕД ОС и Astra Linux.** Trivy ищет кандидатов для РЕД ОС по RHEL, для Astra — по соответствующему выпуску Debian. В карточке хоста отдельно видны кандидаты и CVE с бюллетенем производителя для установленного пакета. Только подтверждённые таким способом CVE добавляются из этого сравнения в риск хоста. Совпадение с MaxPatrol учитывается один раз. [SBOM и Trivy](help:assets-list).
- **Бюллетени производителей ОС.** В поставку включены справочники РЕД ОС и Astra Linux. Их можно обновить в настройках VM или перенести в закрытый контур архивом `oval-full.zip`. После обновления STools автоматически ставит SBOM в очередь на проверку. [Настройки VM](help:vm-settings).

## 22.11.2026

- **Исправлен первый импорт ПО из MaxPatrol VM для SBOM.** Пакеты Linux и установленные приложения теперь сохраняются с первого импорта. В карточке хоста и скачанном SBOM видна полная версия пакета из MaxPatrol, включая номер сборки. Если сохранить инвентаризацию не удалось, причина видна в сообщении задачи и на вкладке «SBOM и Trivy». [Карточка хоста](help:assets-list).

- **Пути к приложениям в «Радаре».** NAT-публикации NetTrace связываются с nginx, маршрутами и backend-сервисами. Цепочка показана слева направо; можно выбирать виртуальные серверы, маршруты и узлы upstream, продолжать путь через внутренние nginx. Для серверов с wildcard-listen доступны ручные привязки IP и сопоставление с Assets по правам пользователя. Неизвестные порты NAT, альтернативы и пробелы в данных отмечены явно; конфигурационная связь не означает подтверждённую доступность. Из схемы можно открыть проверку выбранного сетевого участка в NetTrace. [Радар](help:radar).

## 21.11.2026

- **NetTrace в «Радаре».** Подключение по HTTPS и API-ключу, синхронизация устройств и NAT через общую очередь и расписание. Можно рассчитать участок IPv4 TCP/UDP, открыть шаги пути слева направо и посмотреть правила, трансляции и снимки. История сохраняет запросы и результаты; расчёт можно отменить в очереди. Ограничения, неизвестный порт после NAT и несогласованные снимки показаны явно: разрешённый сетевой путь не подтверждает работу приложения или возможность эксплуатации CVE. [Радар](help:radar).

- **Проверка программ Windows по NVD.** На вкладке «SBOM и Trivy» в карточке хоста нажмите «Проверить по NVD» рядом с распознанной программой. STools учитывает издателя, установленную версию и ОС хоста. Для каждой CVE можно раскрыть условия применимости. Программы, для которых нужно уточнить продукт или версию, отмечены в списке ПО. [Карточка хоста](help:assets-list).

- **Определение пакетов Linux для Trivy.** Если источник передал программу без типа пакета, STools сверяет дистрибутив, издателя и имя пакета с локальной базой Trivy для этого выпуска Linux. При совпадении идентификатор PURL попадает в скачиваемый SBOM и используется при сканировании. [Карточка хоста](help:assets-list).

## 20.11.2026

- **Установленное ПО на вкладке «SBOM и Trivy».** В карточке хоста сразу после инвентаризации видны названия, версии и источники программ. ПО можно искать по названию или версии. CVE MaxPatrol без подтверждённой связи с пакетом собраны в отдельный свёрнутый список. Из него можно открыть карточку уязвимости. [Карточка хоста](help:assets-list).

- **Карточка базы Trivy.** В разделе «Настройки → VM → Справочники» видны дата и источник базы, которой Trivy проверяет SBOM хостов. Можно проверить версию в официальном реестре, принудительно скачать полный снимок или загрузить автономный ZIP с диска. [Настройки VM](help:vm-settings).

- **SBOM и уязвимости хоста.** В карточке актива можно скачать CycloneDX со списком пакетов из MaxPatrol и KSC. Вкладка «SBOM и Trivy» показывает покрытие сканирования, общие уязвимости и находки только одного из источников. Для находок Trivy видны установленная и исправленная версии пакета. [Карточка хоста](help:assets-list).

- **Обновление Trivy в закрытом контуре.** Единый загрузчик для Linux и PowerShell готовит ZIP с базой Trivy. Его можно установить серверным скриптом или загрузить в настройках VM. После смены версии STools автоматически перепроверяет SBOM хостов. [Настройки VM](help:vm-settings).

- **Обновления справочников VM сохраняют накопленные данные.** Архив обновлений добавляет и меняет записи по идентификатору. Карточка справочника отдельно показывает, сколько записей получено, сколько изменилось и сколько всего хранится в базе. [Настройки VM](help:vm-settings).

- **Радар конфигураций nginx.** Перед импортом можно проверить конфигурации, затем найти виртуальный сервер или backend, посмотреть маршруты и директивы с указанием исходного файла и строки. Предыдущие снимки доступны в истории. [Радар](help:radar).

- **Assets: быстрее открывается каталог ПО.** Ускорена загрузка каталога ПО при большом числе хостов и установок из KSC. Подробнее — [ПО](help:assets-software).

- **VM: архивы загружаются пачкой.** В настройках «Справочники» можно выбрать сразу несколько ZIP единого загрузчика — базы уязвимостей, новости и правила. Общая серверная очередь обрабатывает их последовательно и выполняет итоговый пересчёт один раз. Для каждого файла видны состояние и ошибка; можно отменить оставшиеся. После приёма файлов страницу можно закрыть. «Архив новостей» перенесён внутрь «Справочников». [Настройки VM](help:vm-settings).

## 19.11.2026

- **Фильтр риска в обзоре VM.** Флажок «Скрыть средний и низкий риск» оставляет в счётчиках, диаграмме и топах находки высокого и критического риска. Переход из обзора открывает список с тем же отбором. Браузер сохраняет выбор после перезагрузки. [Обзор VM](help:vm-overview).

- **Контейнеры на хостах.** В разделе «Образы контейнеров» в VM и Активах появилась вкладка «По хостам». Она показывает хост, контейнер и состояние из последнего снимка MaxPatrol VM. Фильтры «Запущен» и «Без подтверждённого совпадения в Harbor» можно включать вместе. Ссылка в карточке актива открывает контейнеры этого хоста. [Образы контейнеров в VM](help:vm-images) · [Образы контейнеров в Активах](help:assets-container-images).

- **AV: TOTP для онлайн-подключения KSC.** В настройках подключения можно сохранить секрет второго фактора: он хранится зашифрованным, а одноразовые коды формируются автоматически для проверки подключения, ручного сбора и сбора по расписанию. Сохранённый ключ не отображается; его можно заменить или явно удалить. Подробнее — [Настройки Антивируса](help:ksc-settings).

- **Assets: быстрее открывается реестр.** Поиск, фильтры, фасеты и страницы списка рассчитываются в PostgreSQL по производному индексу. Статусы находок и решения аналитиков учитываются напрямую; неактуальный индекс автоматически перестраивается задачей «Обновление индекса активов» в общей очереди. Ручные изменения карточек обновляют небольшую часть индекса сразу. Экспорт читает данные пакетами из одного согласованного снимка БД.

## 18.11.2026

- **Harbor: диагностика запуска образов.** Скрипт `ops/diagnose_harbor_runtime.sh` для Linux проверяет сопоставление образов с контейнерами, права робота на получение манифестов и причины отказов, включая ограничения политики Harbor. Он читает БД и выполняет GET-запросы к настроенному Harbor, сохраняя отчёт без паролей и токенов. Запуск: `sh ops/diagnose_harbor_runtime.sh`; при нестандартных именах контейнеров укажите имя PostgreSQL и затем API аргументами.

- **VM: Telegram в сборщике и offline-комплекте.** Общий каталог включает 19 публичных каналов. Комплект собирает новости RSS/Atom и Telegram без аккаунта и API-ключей, сохраняет канал, дату и ссылку на пост. Поддерживаются период и доступная история; лимиты, ошибки источников и неполный сбор видны в отчёте. Повторный импорт обновляет изменённые публикации без дубликатов. Медиафайлы не скачиваются. Подробнее — [Настройки VM](help:vm-settings).

- **Assets и VM: быстрый возврат к спискам.** Реестр хостов, список уязвимостей и образы VM запоминают поиск, фильтры, сортировку и прокрутку в пределах текущей сессии. Данные списков и обзоров повторно используются до двух минут; неактивный кэш хранится десять минут. После выхода, смены пользователя или прав сохранённые данные очищаются. Проверка авторизации и обновление статусов задач сохраняют прежнюю частоту.

- **Диагностика производительности.** Добавлены включаемые администратором замеры времени API и SQL, количества запросов и размера ответа, а также скрипт для сравнения списков на тестовом стенде. Тексты SQL, параметры URL и содержимое ответов в отчёт не записываются.

- **VM: Offline для сборщика трендов.** В настройках подключения можно отключить обращения к сборщику, включая диагностику и получение по расписанию. Настройки подключения сохраняются при переключении. Архивы новостей и пакеты сборщика можно загружать и в Online, и в Offline. Подробнее — [Настройки VM](help:vm-settings).

- **VM: быстрее открываются обсуждаемые CVE.** Таблица получает страницу из локальной БД без соединения со сборщиком и без повторного разбора всех публикаций. Сохраняются фильтры, порядок строк, решения аналитиков и риски. Блок «Состояние мониторинга» обращается к сборщику только пока раскрыт; в Offline показывает локальное состояние.

- **AV: большие снимки онлайн-сбора KSC.** Устранён отказ на стадии разбора, когда собранная выгрузка превышала 512 МБ после распаковки. Онлайн-сбор использует уже полученные данные без повторного чтения архива; сохранённые снимки читаются потоком при пересчёте, сравнении и просмотре политик. Ограничение для внешних загружаемых архивов сохранено. После обновления повторите завершившийся ошибкой сбор.

- **Резервное копирование PostgreSQL.** Добавлен скрипт `ops/stools_db.py` с командами `backup`, `verify` и `restore`: полный дамп БД, проверка целостности и восстановление с сохранением прежней базы для отката. В инструкции описаны перенос копии, остановка приложений перед восстановлением и отдельное сохранение файлов выгрузок и ключа шифрования. Исправлен запуск на Python 3.7.3; создание, проверка и восстановление копии протестированы на этой версии.

- **AST: фильтры образов контейнеров.** Добавлены выбор корпоративных и внешних реестров, конкретного реестра, наличия названия, тегов (включая пустые и `none`) и платформы. Фильтры можно сочетать; они сохраняются в ссылке и учитываются при экспорте. Образы без имени показаны как «Без названия», полный ID доступен отдельно. Подробнее — [Образы контейнеров](help:assets-container-images).

- **AV: совместимость сбора установленного ПО.** Онлайн-сбор и PowerShell-сборщик принимают оба названия поля списка программ в ответе KSC: `KLEVP_EA_PARAM_1` и `GNRL_EA_PARAM_1`. Корректный альтернативный ответ больше не отклоняется как ошибка инвентаря. Для хостов с ошибкой в старом снимке нужен новый сбор. Подробнее — [Хосты Антивируса](help:ksc-hosts).

- **Архив новостей в VM.** Архивы ZIP размером от 2 до 64 МиБ теперь проходят загрузку в настройках VM. Форма показывает лимит распакованного `items.jsonl` и подписывает отчёт о последнем успешном импорте.
- **MaxPatrol — ход записи импорта.** В задачах видны текущий шаг записи снимка, число исходных записей при объединении пар хост–CVE, длительность активного запроса PostgreSQL и ожидание блокировки. При неизвестном объёме работы таблица показывает «Без счётчика».

## 17.11.2026

- **Поиск: полная сводка уязвимостей.** Количество находок и максимальный риск теперь учитывают все связанные записи VM, в том числе когда их больше 100. Ограничение применяется только к отображаемому списку: наиболее рискованные находки остаются в его начале.

- **MaxPatrol: импорт CSV больше 2 ГиБ.** Исправлено переполнение счётчика прогресса, из-за которого большая выгрузка завершалась ошибкой `integer out of range` перед разбором CSV, а в задаче оставалась стадия «образы и контейнеры Docker». Существующая история задач сохраняется.

- **Blindspot: очистка писем с заменами в Message-ID.** Если обезличивание нарушает формат служебного идентификатора письма, заголовок исключается с отметкой в отчёте. Письмо проходит строгую самопроверку, корректные идентификаторы сохраняются, исходник не меняется. Добавлена локальная диагностика структуры письма без вывода его содержимого. Подробнее — [Задание очистки](help:toolbox-scrub).

- **MaxPatrol: полная выгрузка и защита снимка хостов.** Нулевой лимит теперь явно запрашивает все записи, включая локальные группы и инвентаризацию Docker. Перед скачиванием сохраняется серверное количество строк, затем проверяются структура CSV и точное совпадение со счётчиком. Убран запрос к последней странице после долгого разбора файла: результат запроса к этому времени мог стать недоступным. Повреждённая или неполная выгрузка отклоняется с сохранением прежних данных. Для проверки полноты ожидание ответа увеличено с 1 до 10 минут; ошибки различают тайм-аут, сбой HTTP и некорректный JSON. После обновления повторите импорт, если ранее получили неполный список хостов. Подробнее — [Настройки VM](help:vm-settings).

- **MaxPatrol: единая диагностика экспорта.** Серверный скрипт одной командой собирает состояние БД, версии, проверки CSV и пагинации в обезличенный архив. Поддерживается Python 3.7 на Docker-хосте без установки дополнительных библиотек. Промежуточные результаты сохраняются для продолжения без повторного скачивания завершённой выгрузки. Рабочая БД не изменяется, исходные данные и токены остаются на сервере. Подробнее — [Настройки VM](help:vm-settings).

- **VM: быстрее импорт MaxPatrol и повторный расчёт риска.** При импорте хостов среди находок Harbor рассчитываются только отсутствующие оценки, для которых доступны данные справочников. Полный пересчёт записывает только изменившиеся оценки и сводки; устранена задержка, возникавшая после первого заполнения рисков. - **Сводка «Данные».** Первый экран настроек показывает свежесть баз, справочников и выгрузок по каждому модулю, со ссылками в нужную секцию. Настройки модулей переехали в общие настройки, шестерёнка доступна всем ролям. Подробнее — [Данные](help:data-status).
- **Планировщик.** Расписания с интервалом и окном, сбор по расписанию у подключений AD и антивируса, часовой пояс сервера задаётся настройкой.
- **MaxPatrol по токену.** VM и база знаний SIEM ходят в MaxPatrol по персональному API-токену, пароль и client secret больше не нужны.
- Иконка вкладки браузера — щит в цвете приложения.

### Assets

- **Новый модуль.** Реестр активов: наблюдения VM, антивируса и AD сопоставляются в один [актив](help:asset), [расхождения](help:discrepancy) между источниками становятся находками. Обзор, список с фильтрами и массовой правкой критичности, задачи синхронизации, пороги в настройках. Подробнее — [Обзор Assets](help:assets-overview).
- **Сети.** Сети с CIDR, [зоной](help:asset-zone), площадкой и владельцем; активы привязываются к сетям по адресу. Поиск по адресу, имени, тегам и VLAN, карточка сети сбоку, расположение хоста как фильтр списка активов. [Группы сетей](help:network-group) с признаками и [правилами отнесения](help:zone-rule) по имени, тегу и адресу — шаблоном со звёздочкой.
- **RackTables как источник.** Сети с VLAN и тегами и внешние адреса создаются в Assets из RackTables; публичные сети попадают в зону External.
- **Пользователи и группы как активы.** Учётки и группы из AD, сеансы и владельцы устройств из антивируса, локальные группы Windows и Linux из VM. Страницы «Пользователи» и «Группы» с карточками: полный состав, права, вхождения, расхождения. Подробнее — [Пользователи](help:assets-users), [Группы](help:assets-groups).
- Обновление активов через DNS: прямые и обратные запросы к указанному серверу.

### Active Directory

- **Сводка домена.** Страница «Сводка»: учётные записи, распределения паролей и входов, контроллеры, [оценка домена](help:domain-score) по категориям и её динамика по снапшотам. Каждое число ведёт в список Assets с тем же составом. Подробнее — [Сводка](help:ad-summary).
- **Новые проверки.** Центр сертификации: ESC6–ESC16 по данным ЦС, стойкость сертификатов (слабые RSA и хеши, ROCA). Контроллеры: NTLMv1, подпись LDAP и SMB, SMBv1, лишние службы, давность перезагрузки. GPO: [пароли в настройках](help:gpp-passwords), LLMNR, WSUS, журналирование PowerShell, аудит. Гигиена учёток, доверия, зоны DNS, репликация на RODC, права на критичные объекты, кластеры Windows.
- **Права через GPO.** Кто и на каких компьютерах входит в локальные группы, с учётом выключенных элементов и неявных групп токена.
- Категории проверок и блок «Как исправить» в карточке находки; обзор отличает «не проверено» от «без находок».
- Сборщики: PowerShell 2.5 и LDAP 1.4 читают всё перечисленное, сбор идёт порциями с паузами и щадит контроллеры, выгрузка пишется потоком и меньше держит в памяти.

### Антивирус (KSC)

- **Политики.** [Политики](help:av-policy) отдельно от задач, карточка политики с вкладками «Оценка» и «Настройки», [профили](help:av-profile), активные на хосте по тегам. Словарь настроек KES для Windows: политика читается по компонентам человеческими названиями, оценка по правилам «компонент выключен», «только уведомлять».
- **Исключения и сетевые правила.** Разделы «[Исключения](help:av-exclusion)», «Сетевые правила» и «Изменения» с поиском и фильтрами, карточки с той же записью в других политиках, опасные исключения (диск целиком, каталоги с правом записи, маски исполняемых).
- **Хосты.** Панель хоста с вкладками, фильтр по состоянию компонента защиты, тегу и политике, статус устройства по KSC с причинами, пользователи и сеансы устройства.
- Журнал изменений между сборами: политики, привязка, профили, настройки. Сборщик 1.4 читает теги, профили, пользователей и сеансы.

### SIEM Rules Analyzer

- **Threat Hunting.** Новый раздел: [библиотека хантов](help:hunt) с редактором запросов и проверкой, ночные прогоны по расписанию, [большие ханты](help:deep-hunt) кусками с паузой на время ночного прогона, находки со статусами платформы, планировщик с очередью и порядком хантов. Ханты с техникой — отдельный слой в матрице ATT&CK. Подробнее — [Библиотека](help:siem-hunting-library), [Планировщик](help:siem-hunting-scheduler).
- **База знаний по API.** Подключение к базе знаний MaxPatrol в настройках, сбор правил с наборами установки и статусом «установлено в SIEM», фильтры «в SIEM», «набор установки», «папка» в инвентаре правил, [профиль инсталляции](help:installation-profile) с табличными списками.
- В теле правила подсвечиваются табличные списки, которых нет в снапшоте; карточка находки анализатора объясняет суть проверки и даёт совет. Гигиена SIEM на общих статусах находок.

### Vulnerability Management

- **Новая формула [риска](help:vm-risk)**: вероятность × тяжесть × ценность, [KEV](help:kev) как факт эксплуатации. Карточка расчёта с весами, фильтр и признак KEV в списке.
- **[Справочники](help:vm-references) одним архивом.** Скрипты для Windows и Linux собирают NVD, EPSS, KEV и CTID в один архив, загрузка распознаёт файлы по именам и докачивает ленту с места обрыва.
- Статусы на паре «хост × CVE»: список по умолчанию показывает открытые, массовая смена статуса. Локальные группы хостов после импорта.

### ToolBox

- **Новый модуль.** [Очистка файлов](help:scrubbing) перед передачей: загрузка файла или текста, сканирование (адреса, хосты, домены, учётки, SID, секреты), предпросмотр находок, применение с самопроверкой результата, обратный перевод ответов по таблице [псевдонимов](help:alias). Настройки: слова и подсети, срок хранения. Подробнее — [Обзор ToolBox](help:toolbox-overview).

### Исправлено

- Задачи сбора можно снять, в том числе осиротевшие после перезапуска; ход записи находок виден порциями.
- Вход в AD по NTLM (ДОМЕН\имя) работает; ответ контроллера с ошибкой прерывает сбор, а не даёт неполный снапшот.
- Неполный сбор AD и антивируса не «устраняет» находки непроверенных проверок; смена версии анализатора не даёт ложных «устранена».
- Доверие корпоративному удостоверяющему центру: файл сертификатов сервера подключается настройкой.
