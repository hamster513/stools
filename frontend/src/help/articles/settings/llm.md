## Что это

На странице задаются подключения к Ollama, OpenRouter и DeepSeek Platform и отдельная модель для каждой действующей задачи. Можно одновременно использовать локальные эмбеддинги, DeepSeek для разметки и другую модель OpenRouter для анализа угроз.

## Как читать

### Подключения

- **Ollama** — адрес локального сервера, например `http://ollama:11434`. Один сервер используется всеми задачами, которым назначена Ollama.
- **OpenRouter** — API-ключ из [личного кабинета](https://openrouter.ai/keys). Каталог включает модели разных производителей и бесплатные варианты `:free`.
- **DeepSeek Platform** — отдельный API-ключ из [личного кабинета](https://platform.deepseek.com/api_keys). Запросы отправляются напрямую в DeepSeek.

Ключи провайдеров хранятся отдельно и шифруются на сервере. Они не возвращаются в интерфейс: пустое поле при наличии отметки о сохранённом ключе использует этот ключ. Новый ключ заменяет старый. Кнопка удаления действует только после сохранения, удаление можно отменить. При переключении провайдера задачи ключ другого провайдера не используется.

## Назначения задач

| Задача | Что выполняет | Какие данные использует |
|---|---|---|
| Поиск кандидатов ATT&CK | Получает эмбеддинги и находит близкие техники | Публичные техники и очищенные выжимки правил |
| Разметка правил SIEM | Выбирает техники из кандидатов | Выжимка правила после очистки и проверки на утечки |
| Перевод ATT&CK | Переводит названия и описания техник | Публичная база ATT&CK |
| Перевод и объяснение CVE и новостей | По кнопке переводит материал на русский или объясняет суть, последствия, версии и действия | Разрешённые публикации и контекст CVE; без инвентаря хостов, образов и комментариев аналитика |
| Анализ публикаций об угрозах | Выделяет продукт, затронутые версии и признаки эксплуатации | Текст и заголовок публикации из разрешённого источника |

В каждой карточке выберите провайдера, затем модель из его каталога. Для эмбеддингов доступны Ollama и OpenRouter; DeepSeek не предоставляет этот API. Для локального поиска подходит установленная модель `bge-m3`.

Параметры задачи:

- **Включена** — разрешает обработку этой задачи. Выключение сохраняет выбранную модель.
- **Только локально** — ограничивает задачу Ollama; при включении для внешней модели нужно выбрать локальную модель.
- **Таймаут** — время ожидания ответа от 5 до 1800 секунд.
- **Режим рассуждения** — используется задачами генерации; может увеличить время ответа.

Общий переключатель «Обращения к моделям разрешены» выключает обращения всех задач, включая перевод и объяснение из карточек. Ручная проверка подключения остаётся доступной. Для разметки SIEM должны быть настроены и включены обе задачи: поиск кандидатов и разметка. Перевод и анализ публикаций не зависят от этих двух назначений.

## Как настроить

1. Введите адрес Ollama и/или ключи нужных провайдеров.
2. Выберите провайдера в нужной задаче и нажмите «Обновить модели». Для DeepSeek каталог запрашивается с введённым или сохранённым ключом.
3. Выберите модель, настройте таймаут и нажмите «Проверить подключение».
4. Нажмите общую кнопку «Сохранить».

Проверка выполняется с несохранёнными параметрами и только для выбранной задачи. Для эмбеддингов запрашивается вектор; для остальных задач — короткий JSON-ответ. Внешние проверки оплачиваются по тарифу модели, у бесплатных моделей действуют ограничения. Проверка не запускает обработку всего набора данных.

Если выбранная модель отсутствует в каталоге, она остаётся видна с отметкой; выберите доступную замену. Ошибка модели не переключает задачу на другого провайдера. При смене модели эмбеддингов или адреса сервера нужные векторы будут вычислены заново; векторы разных моделей не смешиваются.

## Граница данных

Публичные и обезличенные данные разрешено направлять внешним моделям. Внутренние данные разрешены только локальным моделям. Сервер проверяет эту границу перед выполнением задачи; неизвестная категория не разрешает внешнюю обработку.

Очистка правил SIEM и проверка на утечки выполняются до обращения к модели. Для публикаций сохраняется отдельное разрешение источника на LLM-обработку; запрет для Telegram-origin сохраняется. Если источник или публикация явно помечены внутренними, внешняя модель не вызывается. В анализ публикаций не добавляются инвентарь, имена хостов или результаты сопоставления с нашими активами: сопоставление выполняется локально.

Выбор внешней модели сам по себе не обезличивает данные. Для задачи, работающей с внутренними материалами, используйте «Только локально» и Ollama.

## Существующие настройки

При первом открытии прежние общие параметры преобразуются в назначения задач без смены провайдера, модели и ключей. Общий запрет обращений сохраняется. Если ранее был выбран DeepSeek, эмбеддинги остаются на Ollama. После сохранения задачи настраиваются независимо. Старые результаты не стираются и не пересчитываются автоматически только из-за смены модели.
