## Что это

Сводка места, занимаемого PostgreSQL, файлами модулей и базой коллектора новостей. Каждый объект учитывается один раз. Общие данные платформы и системное пространство PostgreSQL показаны отдельно, чтобы не приписывать их нескольким модулям.

## Как читать

Вверху — измеренный общий объём, база PostgreSQL, файлы модулей и SQLite коллектора. Ниже — таблица по модулям, отсортированная по размеру. Нажатие на модуль раскрывает размеры таблиц и индексов. Число строк — оценка статистики PostgreSQL, а не полный пересчёт записей.

«Данные БД» включают TOAST и служебное пространство таблиц. Системное пространство включает каталоги PostgreSQL, последовательности и остаток, не отнесённый к прикладным таблицам. Размер базы может не уменьшиться сразу после удаления записей: PostgreSQL оставляет освобождённое пространство для повторного использования.

Файлы измеряются по выделенным блокам в каталоге данных API: архивы SIEM, выгрузки AD/KSC, данные VM и других модулей. Символические ссылки пропускаются, жёсткие ссылки учитываются один раз. Обход ограничен по времени и числу записей. При ошибке или достижении предела замер отмечается как неполный; это не нулевой объём.

Для коллектора учитываются база SQLite, WAL и SHM. Если коллектор недоступен или старая версия не сообщает размеры WAL/SHM, общий объём отмечается как неполный. Отключённое подключение обозначается отдельно. Свободное место относится только к файловой системе каталога API, а не к серверу PostgreSQL или коллектору.

**Вне охвата:** образы Docker, резервные копии, WAL PostgreSQL, данные внешних систем и отдельно развёрнутого IRP. Это учёт данных STools в перечисленных источниках, а не всего занятого диска сервера.

## История роста

Доступны периоды 7, 30, 90 и 365 дней и выбор модуля. На графике показан последний замер каждого дня в часовом поясе платформы; точные значения и время доступны в раскрываемой таблице. Неполные замеры не соединяются линией. Общий рост рассчитывается только для полных замеров с одинаковым составом источников; отрицательное значение означает уменьшение объёма.

История начинается с реального первого замера: прежние значения не восстанавливаются. Хранятся до 1000 замеров за последние 365 дней. Очистка этой истории не удаляет данные модулей. Открытие страницы читает сохранённые замеры и не сканирует хранилище повторно.

## Как настроить

В [общем расписании](help:sync-schedules) есть задача «Замер объёма хранилища» в разделе «Платформа». По умолчанию она включена ежедневно в 03:00 в часовом поясе платформы. Первый замер выполняется при первом тике планировщика после установки обновления. Можно выбрать другие дни, время или интервал, выключить либо удалить расписание; перезапуск не отменяет эту настройку.

Администратор платформы может нажать «Измерить сейчас». Параллельный запуск не допускается, повторный ручной замер доступен через минуту. Планировщик Threat Hunting не меняется.

## Сроки хранения и очистка

На этой же странице администратор задаёт сроки хранения служебных данных. Начальные значения:

| Данные | Хранить, дней |
| --- | ---: |
| События синхронизации в VM | 14 |
| Журнал изменений коллектора | 30 |
| Успешные служебные задания | 30 |
| Ошибки служебных заданий | 90 |
| История запусков источников | 90 |

Допустимо от 1 до 3650 дней. Отдельный переключатель разрешает удалять ненужные временные файлы импорта; по умолчанию он включён. Активная загрузка защищена. У квитанций очищается содержимое старых пакетов, а отметки обработки сохраняются для проверки повторной доставки. Журнал коллектора сокращается только при возможности безопасно восстановить синхронизацию.

1. Измените сроки и нажмите «Сохранить сроки». Сохранение не удаляет данные; после него автоматически обновляется расчёт.
2. Проверьте «Предварительный расчёт»: категории, количество записей к очистке, защищённые записи, приблизительный объём, состояния и причины. «Рассчитать очистку» обновляет его вручную.
3. Нажмите «Очистить по расчёту» и подтвердите конкретные категории и количества. Расчёт действует 15 минут и используется один раз. После изменения сроков или истечения времени нужен новый расчёт. Перед выполнением сервер повторно проверяет условия; результат может отличаться от предварительного.
4. После запуска расчёт обновляется. В «Последней очистке» доступны результат по категориям и предупреждения. Для актуальных размеров хранилища запустите отдельный замер.

Недоступность коллектора не означает нулевой объём: неизвестные значения показаны как «Нет данных», причина — в таблице и предупреждениях. Очистка этой части пропускается явно. Частичное выполнение видно в результате последнего запуска.

**Что сохраняется:** публикации, справочники, текущие связи CVE, решения аналитика и сохранённые ответы ИИ, включая платные. Удаление публикаций по сроку не включено: сначала нужен архив. Защищённые категории и причины сохранения перечислены в расчёте.

**Объём — оценка данных, а не гарантированное освобождение диска.** После удаления строк PostgreSQL может сохранить выделенное место для повторного использования. Автоматическое сжатие базы через `VACUUM FULL` не выполняется.

В [общем расписании](help:sync-schedules), в разделе «Платформа», есть задача «Очистка хранилища». Она изначально выключена; включается отдельно и использует сохранённые сроки. Расписание очистки и расписание замеров настраиваются независимо.

Сокращение журнала коллектора сопровождается сохранением согласованного снимка. Если позиция синхронизации устарела, VM восстанавливается из снимка и получает следующие изменения. До завершения восстановления остаётся доступно предыдущее поколение данных. Для архивного переноса после очистки используется новый формат снимка, который требует обновлённой VM. Содержимое событий в VM заменяется контрольными суммами: проверка повторной доставки продолжает работать.
