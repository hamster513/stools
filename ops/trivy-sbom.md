# Проверка SBOM хоста в закрытом контуре

Образ API содержит Trivy 0.76.2 для целевой архитектуры и официальный справочник уязвимостей на момент сборки. Исходный слой справочника можно обновить при сборке через `docker buildx build --no-cache-filter trivy-db`. Снимок от 20 ноября 2026 года занимает около 1,7 ГиБ после распаковки. При развёртывании готового образа проверка доступна сразу.

STools передаёт локальному `trivy sbom` тот же CycloneDX 1.6 JSON, который скачивается из карточки актива. Процесс работает без сети, отключает телеметрию и использует базу в режиме чтения. Поле «проверено» считает уникальные компоненты, которые Trivy вернул в списках пакетов. Приложения без поддерживаемого пакетного идентификатора, версии или совместимого выпуска ОС остаются в инвентаре со свойством `stools:unassessed-reason`. Для ранее опубликованного результата сохраняются версия сканера и дата базы.

Полнота совпадений зависит от данных источника. Например, для RPM Rocky Linux и RHEL Trivy учитывает архитектуру пакета. При её отсутствии часть бюллетеней для конкретных архитектур пропускается. STools передаёт наблюдаемую архитектуру, имя и версию исходного пакета, когда они доступны. Для процесса заданы ограничения в две минуты и 64 МиБ JSON-вывода. Превышение любого ограничения завершает проверку с ошибкой.

## Обновление в закрытом контуре

Распакуйте **Единый загрузчик — Linux и PowerShell** из настроек справочников VM на компьютере с интернетом. Для загрузки достаточно Python 3.11+. Выберите Trivy в меню или выполните одну из команд.

```sh
sh download-stools.sh --datasets trivy --mode full
```

```powershell
.\download-stools.ps1 -Datasets trivy -Mode Full
```

Скрипт сохранит `trivy-full.zip` в новом каталоге внутри `stools-downloads`. В режиме `--mode updates --period 7d` получается `trivy-updates.zip` с таким же полным снимком. Загрузчик сверяет SHA-256 с манифестом официального реестра и использует локальный кэш при повторном запуске. Период влияет на источники с частичными обновлениями.

Перенесите ZIP и скрипт `update-trivy-db.sh` на Linux-сервер STools. Из каталога с файлами установите снимок командой

```sh
sh update-trivy-db.sh trivy-full.zip
```

По умолчанию используется контейнер `stools-api-1`. Для другого имени передайте его вторым аргументом. Импорт также доступен администратору VM через **Настройки → VM → Справочники → Загрузить архивы**. При работе через Docker Compose команда внутри контейнера принимает ZIP из стандартного ввода.

```sh
docker compose -f ops/docker-compose.yml exec -T api python -m api.cli import-trivy-db < trivy-full.zip
```

Сервер проверяет SHA-256 слоя, метаданные и открытие базы локальным Trivy. После успешной проверки переключается активный снимок в `$STOOLS_DATA_DIR/trivy-updates`. Для распаковки требуется место под новую базу и сжатый слой. Идущие проверки заканчивают работу с прежней версией. Дата новой базы входит в ключ фоновой очереди SBOM, поэтому хосты перепроверяются автоматически. Повтор действующего снимка сохраняет очередь. Устаревший или повреждённый снимок отклоняется.

До первой установки архива сканер использует ранее настроенный каталог `$STOOLS_DATA_DIR/trivy` либо встроенную базу API. Формат OCI-слоя описан в [документации Trivy](https://trivy.dev/docs/latest/advanced/self-hosting/).
