# Диагностика экспорта MaxPatrol

Скопируйте **один файл** `ops/diagnose_mpvm_export.py` на сервер STools и запустите на Docker-хосте:

```bash
python3 diagnose_mpvm_export.py --container stools-api-1
```

Нужны Python 3.7+ на хосте и доступ к Docker. Зависимости устанавливать не нужно: библиотеки приложения и `importlib.metadata` загружаются только внутри API-контейнера, с его версией Python. Версия сборщика 1.1 поддерживает Python 3.7 на сервере; версия скрипта и Python показываются при запуске. Если API-контейнер единственный, `--container` можно опустить. При нескольких экземплярах сборщик не выбирает их наугад.

В конце в текущем каталоге появится **один `mpvm-diagnostics-*.tar.gz`**. Передавайте этот архив целиком. Он содержит `summary.txt`, `report.json` и `events.jsonl`. При ошибке запуска создаётся отдельный `mpvm-launcher-error-*.tar.gz`, если каталог вывода доступен для записи.

## Что собирается

- Версии Python и библиотек, контрольные суммы установленного клиента и парсера, ID образа, перезапуски контейнера, ограничения памяти, свободное место.
- Количество хостов и находок, статистика таблиц, последние импорты и задачи, состояния ожидания PostgreSQL. Каждый запрос выполняется в отдельной транзакции только для чтения с ограничением 5 секунд. Ошибка одного наблюдения сохраняется в отчёте.
- Запрос импорта установленной версии приложения с текущими фильтрами. Малый CSV с `limit(3)`, страницы со смещениями 0–4 и **один полный CSV** с настроенным лимитом подключения.
- Независимый разбор CSV и разбор настоящим парсером приложения: строки, пустые записи, ошибки структуры, хосты, строки с CVE, обезличенные начало и конец. Число уникальных хостов/CVE ограничено 100 000; при достижении лимита явно показано `capped: true`.
- Границы полного результата, дополнительная проверка на сырых строках при расхождении счётчиков, запрос с явным большим `limit(N)` и проверка смещений `N−1`/`N`. Повтор граничной страницы показывает, изменился ли ответ за время проверки. `row_count` сохраняется как наблюдение, без предположения о точности этого API.
- HTTP-коды, длительности, структура ответов, цепочки классов ошибок и категории причин. Успешное скачивание или две записи на границе сами по себе не доказывают полноту выгрузки либо величину расхождения.

Сборщик не импортирует данные, не меняет рабочую БД и не перезапускает сервисы. Он создаёт запросы экспорта на MaxPatrol и скачивает данные, поэтому использует его ресурсы. Полный прогон может занять десятки минут. Бюджет по умолчанию — 60 минут; API-запросы ждут ответ до 10 минут в пределах общего бюджета. Каждые 30 секунд выводится сообщение, что процесс работает.

## Данные, ограничения и продолжение

Сырые CSV, ответы и токены запросов хранятся **только на сервере**, в `${STOOLS_DATA_DIR:-/data}/vm/diagnostics/<RUN_ID>/private`. Каталоги запуска имеют права `0700`, файлы — `0600`. В архив они не включаются. Хосты, адреса, неизвестные значения ответов заменяются HMAC-идентификаторами с солью, которая также остаётся на сервере. Тексты задач и исключений, конфигурация подключения и содержимое HTTP-ответов не публикуются.

Для скачивания нужен объём полного CSV плюс запас: по умолчанию сборщик оставляет свободным не менее 1 ГиБ. Весь CSV не помещается в память. JSON ограничен 1 МиБ; при разборе CSV действует предел 1 МиБ символов между записями, выданными каждым парсером, и 128 столбцов заголовка. Достижение диагностического ограничения явно отмечается как незавершённый разбор; это не заключение о повреждении данных MaxPatrol. Установленный парсер дополнительно сохраняет собственное ограничение длины поля.

Ctrl+C останавливает именно процесс диагностики и сохраняет частичный архив. Повторный запуск с тем же идентификатором:

```bash
python3 diagnose_mpvm_export.py --container stools-api-1 --resume RUN_ID
```

Завершённый CSV повторно не скачивается: проверяются его контрольная сумма, исходный токен запроса и настройки источника. Успешные проверки берутся из контрольных точек; наблюдение стабильности границы повторяется. Истёкший токен не заменяется новым для старого CSV. При изменении настроек нужен новый запуск. Одновременное продолжение одного запуска блокируется.

При обрыве скачивания остаётся `.part`; он никогда не считается готовым CSV. Продолжение скачивает этот CSV заново, сохранив предыдущую неполную попытку. После SIGKILL, остановки контейнера или исчерпания диска финальный архив не гарантирован, но записанные контрольные точки остаются. Приватные файлы автоматически не удаляются — после завершения расследования удалите каталог нужного запуска на сервере.

Опции: `--output КАТАЛОГ`, `--budget-minutes N` (1–240), `--reserve-gib N`. Версия и хеш самого скрипта входят в отчёт. Результаты проверок на синтетических данных не заменяют контрольный запуск на конкретном MaxPatrol.
